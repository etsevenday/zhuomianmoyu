# B9 联机协议用例表

批次：B9 联机协议与本机回环（[开发记录](<../开发记录/B9 联机协议.md>)）。按 [测试用例准则](<00 测试用例准则.md>) 编写。
依据：[NET-EVAL-001](<../开发记录/NET-EVAL-001 真实联机接入评估.md>) §4、§6 第 2 步、§8 小实验结果；`doc/策划案/同图房间 v0.1/` 01 §4—§6（0.2）、02 NET-01—07；`文案交接 v0.1/04` TXT-ROOM-029—048、065—071。

本批做的是**不需要 Steam 的那一半**：房主权威的联机协议（内核 `RoomLink`）和一个按 Steam 房间规矩做的本机回环服务，NET-02—05 的规则部分在这里自动测。回环服务的规矩照 §8 实测：房间所有者唯一、所有者走了自动交给剩下的人、只有所有者能写房间数据（别人写不报错但不生效）、每人只能写自己的成员数据、消息点对点发。

执行入口：
- N：`dotnet test web/Moyu.sln`（`B9CaseTests.cs`）。内核里用一个内存假房间服务连 4 个 `RoomLink`，能控制消息顺序、重复、延迟、掉线。
- B：`node tools/verify/b9.mjs --release`。脚本在本机起回环服务（`tools/verify/relay.mjs`），开 4 个互相隔离的浏览器上下文（各自一份存档）当 4 个人，网址带 `?net=<回环地址>&name=<名字>`；"在 Steam 里点接受邀请"、"拔网线"、"重发一条旧消息"由脚本直接让回环服务做。
- 回归：`b3.mjs --release`（网页模拟房间不受影响）、`b8`、`b2`、`b1`、`b0`。

## 本轮失败归类

| 用例 | 现象 | 归类 | 处理 |
| --- | --- | --- | --- |
| B9-08（调试） | 重进的 B 没排在最后，或 C 选不到 B 的旧位置 | 脚本错 | 测试里 D 先离开又重进，重进的人被重新安排、正好落在 B 空出的位置。改成先让 C 选 B 的旧位置，再让 D 离开重进。预期没有放宽 |
| B9-28、B9-25（调试） | 读不到地图；人数读成 null | 脚本错 | 新档的偏好里没有地图，改为在场景上加 `data-map` 来读；面板关着时没有人数，改为先打开房间面板 |
| 全部（调试） | 不带 `?net=` 的页面控制台报错 | 实现缺陷 | JS 返回 null、C# 按 `JsonElement?` 收会抛异常。改成返回 JSON 字符串、收 `string?` |
| B9-28（调试） | B、C、D 没有"已跟随房间前往…" | 实现缺陷 | 成员收到新快照后走和模拟房间一样的跟随流程 |
| B9-29（调试） | 找不到"跟随房主" | 脚本错 | 标记在收藏页说明里，B 的面板还停在看鱼缸那一页，先点返回 |

## 本批不覆盖

| 验收 | 原因 |
| --- | --- |
| NET-01—05 的 Steam 部分（真实 Steam 建房邀请、真实掉线、跨电脑） | B10 接 Steam 后人工测；本批是同一套协议走本机回环 |
| NET-06（没开 Steam） | B10，PC 外壳连 Steam 时才有 |
| NET-07 的真实好友数据 | B10；本批列表的数据来自回环服务 |
| 对方没开游戏时点邀请被拉起 | 要自己的 App ID，见 NET-EVAL-001 §8 |
| B9-29 里场景主题和成员外观的差异 | 新档只有基础主题和外观，脚本做不出差异。显示走的是和网页模拟房间同一套代码（B3-37 测了跟随房主）；B10 两台电脑人工测时一起看 |
| PC 外壳多开 | 评估原计划在本批让 PC 外壳多开 4 个，改为 4 个浏览器上下文：页面代码同一份，外壳这一层要到 B10 有了 Steam 传输才有东西可测，届时一起做 |
