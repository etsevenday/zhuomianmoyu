# B10 Steam 联机用例表

批次：B10 接上 Steam（[开发记录](<../开发记录/B10 Steam 联机.md>)）。按 [测试用例准则](<00 测试用例准则.md>) 编写。
依据：[NET-EVAL-001](<../开发记录/NET-EVAL-001 真实联机接入评估.md>) §6 第 3 步、§8 小实验结果；`doc/策划案/同图房间 v0.1/` 01 §5、§5.1（Q26）、§5.2（Q27）、§6，02 NET-01—07；`文案交接 v0.1/04` TXT-ROOM-035—048、065—071。B9 的协议（`RoomLink`）和页面不改规则。

本批把 B9 的本机回环服务换成 PC 外壳里的 **Steam 小程序**（`pc/steam`，C# + Steamworks.NET，先用公用测试 ID 480），并补上 B9 推过来的 **PC 外壳多开**：
- Steam 小程序把 Steam 房间、好友、网络消息翻成和回环服务**同一种事件**，页面只认这一层；Steam 没开、没登录时报"未就绪"，页面房间入口显示 TXT-ROOM-065，单机照常。
- 小程序另有一种测试用的**回环模式**（只在外壳测试模式下能开）：不碰 Steam，改连 B9 的回环服务。这样外壳、小程序进程、页面这一整条链能在一台电脑上开 4 个外壳自动测，CI 也能跑。
- 事件怎么从 Steam 的状态里整理出来（谁进谁出、所有者变了没有、房间数据和成员资料是不是新的、好友算哪种状态）写成内核里的纯逻辑 `LobbyTracker`，自动测；小程序只负责调 Steam。

执行入口：
- N：`dotnet test web/Moyu.sln`（`B10CaseTests.cs`）。
- B：`node tools/verify/b10.mjs --release`。脚本起回环服务，以测试模式开 4 个 PC 外壳（各自数据目录、各自调试端口），小程序走回环模式；另开 1 个正常模式的外壳看 Steam 模式。CI 上 `b6` 用打好的包再跑一遍。
- M：两台电脑、两个互为好友的 Steam 账号，用 PC 试玩包人工测（发给策划，像 #9 那样）。
- 回归：`b9`、`b3`、`b4`、`b8`、`b2`、`b1`、`b0`（都带 `--release`）。

## 本批不覆盖

| 验收 | 原因 |
| --- | --- |
| 对方没开游戏时点邀请被拉起加入 | 480 会拉起 Valve 的 Spacewar，换自己的 App ID 后测（NET-EVAL §6 第 4 步）。拉起时带的 `+connect_lobby` 参数本批已接好，由 B10-27、28 用回环模式测 |
| 真实 Steam 的 4 人房、满员 | 只有 2 个账号。4 人和满员的规则由 B9（N、B）和 B10-22—25 用回环模式测 |
| 真实 Steam 的版本不一致 | 要两个不同构建的包同时联机，人工成本高；规则由 B9-16、B9-26 测，Steam 下读写的是同一个 ver 键 |
| 正式 App ID | 还没办，换 ID 时改小程序里的一个常量，重跑人工用例 |
