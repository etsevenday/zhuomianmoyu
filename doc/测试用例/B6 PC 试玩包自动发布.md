# B6 PC 试玩包自动发布用例表

批次：B6 PC 试玩包自动发布（[开发记录](<../开发记录/B6 PC 试玩包自动发布.md>)）。按 [测试用例准则](<00 测试用例准则.md>) 编写。
依据：用户 2026-11-18 要求"每次提交后 GitHub Actions 自动打包发布"PC 版，给策划试玩。没有策划案验收编号，用例号自编，验收列写要达成的事。

**不做**：安装包、代码签名、自动升级、Steam。没签名，第一次打开 Windows 会提示"已保护你的电脑"，要点"更多信息 → 仍要运行"。

执行入口：
- B：`node tools/verify/b6.mjs [--release]`：本地打包（`pc/pack.mjs`），用资源管理器同一套解压（`Shell.Application`）解开，检查包内容；以正常模式（不是测试模式）启动包里的 `桌面摸鱼.exe` 看载入、构建号、采集程序；再用包里的 exe 跑全套 `b4`、`b5`（`MOYU_PC_APP` 指向它）。
- 线上：`node tools/verify/b6.mjs --online`：从 README 里的固定地址下载 Releases 上 `pc-latest` 的包，跑同一套，构建号要等于 `origin/main` 的提交。
- S：读工作流和打包脚本。
- M：在没装 .NET、没装 Node 的电脑上下载解压双击。

## 本轮失败归类

| 用例 | 现象 | 归类 | 处理 |
| --- | --- | --- | --- |
| （线上）ab801d4 的 pc 任务 | 打包成功，发布那一步 bash 报 `→: command not found`，没发出去（标签没动） | 实现缺陷（工作流脚本） | 说明文字里的英文双引号把 shell 的字符串截断了；B6-06 原来只按字面查工作流，查不出。说明改用 heredoc 写；B6-06 加上真用 bash 试跑发布脚本、核对发出的标题和说明，用旧写法试过会报失败 |
| B6-04（b5 的 B5-07） | 点小熊前守卫发现那一点上不是小窗（是 ShellExperienceHost"新通知"），停止点击，脚本中断；跑了三次两种窗口 | 测试环境 | 截图看到是 Claude 桌面应用的通知弹窗：开发方在跑测试时发进度消息，应用在右下角弹通知，正好盖住默认在右下角的小窗。之后跑测试时不发消息；b5 点小窗前改成等到那一点上真是小窗再点（最多 10 秒，守卫照样把关）。没有点到别的窗口上 |
| B6-04（b5 的 B5-05、B5-07、B5-09） | 单独用包跑 b5：一次 B5-05 少计 1；一次 B5-05 采集程序一个点击都没报、B5-07 少一次、B5-09 没穿透，紧接着再跑一次 18/18 | 测试环境（测试中真鼠标被动过） | 按下到松开之间指针挪了超过 5 个逻辑像素就算拖动不计，指针被挪开小窗也会切穿透，都和"有人在动鼠标"对得上；同一个包再跑全过。发送器加检查：点击、拖动完了指针不在该在的地方就报"有人在动鼠标"并停下，不再当成计数结果；b5 的 B5-05、B5-09 明细加上采集程序报来的点击数，以后能分清是哪一层少的。预期没改 |
