# INPUT-EVAL-001 评估回稿：跨程序输入走哪条路

日期：2026-11-18　|　回复：[评估请求](<../策划案/跨程序输入路线评估 v0.1/01 开发可行性评估请求.md>)、issue #8
依据：B4 PC 窗口已在 10ebb72 上线，Electron 外壳是实测过的（`b4.mjs --release` 26/26，用户真机试玩）。本稿里"跨程序采集"的部分都还没做实验，标了"待实测"的不能当成已经验证。

**用户决定（2026-11-18）**：按 B 做，开发方已开工，批次名 B5 PC 后台输入。下面 §3 的最小验证就是 B5 的验收底子；跑出来的结果回填到 B5 用例表，"待实测"的条目以那里为准。

## 1. 结论

**推荐 B：在 B4 的 Electron 桌面版上加后台输入。不推荐 A（Windows 助手 + 现有网页）。**

理由一句话：A 需要的本机采集，B 也需要，而且是同一份；A 在这之外还要多做一整套"本机程序 ↔ HTTPS 网页"的连接、配对、两条通道去重和标签页生命周期处理，而这些恰好是风险最大、最依赖浏览器版本的部分。B 只有一条通道，没有这些问题。

| | A：助手 + 网页 | B：桌面版 + 后台输入 |
| --- | --- | --- |
| 难度（只计其他 Windows 程序） | 中偏难 | 中 |
| 难度（连浏览器其他标签页、地址栏） | 难 | 中（和上一行同一件事，不另加成本，见 §2） |
| 已有基础 | 网页玩法全部可用；助手、连接、配对全是新做 | 外壳、透明小窗、穿透、拖窗缩放、存档、单实例都已上线测过；只缺采集 |
| 最大风险 | 浏览器对"公网页面连本机"的权限策略（Chrome 本地网络访问提示）、后台标签页被冻结或丢弃、两通道边界双计/漏计 | 采集程序被杀毒软件当成键盘记录器报警；未签名安装包的 SmartScreen 警告 |
| 工作量（开发方经验估计） | 先做 1 次浏览器连接小实验（通过才继续），之后约 2—3 个批次 | 约 1 个批次（和 B4 差不多），装包/签名另算 |

## 2. 逐题回答

### 2.1 输入范围和排除成本

- **B**：规则只有一条——**落在桌面摸鱼自己窗口上的输入是管理操作，不计；其余一律按工作输入计**。键盘看前台窗口是不是我们的；鼠标看按下那一刻指针下面是不是我们的窗口，并且这一点没有被穿透（外壳本来就记着当前是否穿透，B4 已实现）。浏览器的任何标签页、地址栏，在 B 里只是"别的程序"，和 Word、IDE 一样计，不需要额外适配。所以 B 的两个范围是同一个难度。
- **A，只计其他程序**：助手看前台是不是浏览器进程，是就不计、交给网页自己计。能做，但要处理"用户有好几个浏览器、游戏开在哪个里"的判断。代价是：游戏开在 Chrome 时，在 Chrome 别的标签页里工作一律不计，这是范围上的缺口，不是 bug。
- **A，连其他标签页和地址栏**：助手看不到浏览器里哪个标签页在前面，只能靠网页告诉它"我现在有焦点 / 没焦点"。焦点切换的那一瞬间两边各自判断，按键可能两边都算或两边都不算；不允许用 50ms 合并来糊，就只能在协议里给每次输入对时间顺序，复杂而且仍有边界误差。**难**。

### 2.2 同一次操作只算一次

- **B**：只有一个采集来源（外壳的采集程序），网页那边在 PC 模式下已经一律不计（B4 的 `play.js`），所以不存在两边各算一次。管理操作的排除见上一条：面板、选位、拖窗、收起头像、恢复、缩放都发生在我们窗口上，天然排除。repeat 用"这个键当前是否按着"去重，松开就清；鼠标沿用现有口径，按下到松开算一次、移动超过 5 像素算拖不计。每次合格输入照现在一样调用一次 `OnWorkInput`，不合并、不限速，节点和抽取走原来的内核逻辑。
- **A**：游戏标签页在前台时，网页和助手都能看到同一次按键。需要一方让路（见 2.1），边界上不可能做到完全不双计又不漏计。配对、助手托盘菜单的操作要另行排除。

### 2.3 浏览器连接（只关 A）

现在的发布地址是 GitHub Pages 的 HTTPS 页面，要连本机助手，可选的是 `ws://127.0.0.1:端口` 或 `http://127.0.0.1` 的接口。已知情况（**都待实测**）：

- 浏览器一般允许 HTTPS 页面连 `127.0.0.1`（本机地址算"可信"，不算混合内容）。
- Chrome / Edge 正在推行"本地网络访问"权限：公网页面访问本机时弹提示，要玩家点允许；不同版本覆盖 fetch / WebSocket 的时间不一样。玩家拒绝或企业策略禁用时就连不上。Firefox 的做法也不同。
- 配对：握手时校验 `Origin` 只认发布地址（别的网站伪造不了这个头），再加一次性配对码。本机其他程序能伪造，但本机程序本来就能自己读键鼠，不扩大风险。
- 不用浏览器扩展也能连；如果实测 WebSocket 被拦，就只剩扩展 + Native Messaging，安装负担再加一层。

B 没有这一项：采集程序是外壳自己的子进程，走进程间通信，不经过浏览器。

### 2.4 工作中是否可靠

- **B**：外壳进程活着就采集，小窗收起、被别的窗口挡住都不影响（窗口不在前台时页面会不会被节流、计数有没有延迟，**待实测**；有问题可以关掉 Electron 的后台节流）。关闭程序 = 采集进程跟着退出，不会有离线补算。写权：桌面版是单实例，没有多标签页抢写权的问题。换模式、换地图时，计数是一次一次实时交给内核的，落在当前模式上，不会投错旧计数。
- **A**：标签页隐藏时 WebSocket 一般还活着，但 Chrome 会冻结或直接丢弃长时间在后台的标签页（省内存功能），这时助手得停采、不缓存，否则会把没人接收的时段补成奖励；页面恢复后要重新握手、对齐序号。多标签页时助手只能发给持有 Web Locks 写锁的那一页，写锁换手时要重新配对。每一项都能做，但都要单独测。

### 2.5 部署与维护

| | A | B |
| --- | --- | --- |
| 玩家要装 | 助手程序（常驻托盘）+ 打开网页 + 可能的浏览器权限确认 | 一个安装包 |
| 普通用户能否自己装 | 能，但多一步配对 | 能 |
| 杀毒 / 签名 | 助手采集全局键鼠，有被报的可能；未签名有 SmartScreen 警告 | 同左（采集方式一样）。安装包约 100MB 级 |
| 升级 | 网页自动更新，助手要另行升级，还要处理两边协议版本不一致 | 外壳和页面一起升级，版本永远一致 |
| 卸载 | 两处 | 一处 |

两条路都必须标"不支持"的（**待实测确认清单**）：锁屏和 UAC 安全桌面（系统不让任何程序读）、以管理员身份运行的程序窗口（权限比我们高时可能读不到）、远程桌面里的程序、独占输入的全屏游戏。

采集方式两条路一样：Windows Raw Input 的 `RIDEV_INPUTSINK`（不在前台也能收到输入），只用来判断"按下了一次 / 点了一次"，不读字符、不存按键内容和时间线、不拦截输入，原输入照常到用户正在用的程序。比低层键盘钩子更不像记录器，杀毒误报风险也低一些（**待实测**）。

### 2.6 推荐

B。A 不比 B 省事：A 的采集部分和 B 一样，额外的连接、配对、去重、后台恢复都是 B 没有的成本，而且有一部分（Chrome 权限提示）不在我们手里。

**B 的最小试玩范围**：B4 外壳 + 后台采集 + 计数接入现有内核；网页版保持现状（只计页面内）；Steam 真联机、安装包签名、自动升级都不在这一批。复用：C# 内核、Blazor 全部页面、所有美术资源、B4 外壳（全部），只新增采集程序和外壳里的转发。

另外提醒：05 原文提过，Steam 的游戏内覆盖层（Overlay）对 Electron 这类浏览器式窗口另有要求。这和后台输入无关，但走 B 就意味着将来接 Steam 时要把这一项算进成本；如果到时迁 Godot，采集程序可以原样带过去。

## 3. 最小验证（B）

全部用脚本跑，用 Windows `SendInput` 往记事本里模拟真实按键和点击：

| 编号 | 怎么验 | 通过标准 |
| --- | --- | --- |
| EVAL-01 | 小窗开着，前台是记事本，按 100 次键 | 计数 +100；记事本里出现 100 个字符（输入没被拦） |
| EVAL-02 | 按住一个键 2 秒；在小窗面板上点 10 次；拖窗、缩放、收起、恢复；穿透区点 1 次；在记事本里拖选文字 | 按住只 +1；小窗上的操作 +0；穿透点击 +1；拖选 +0 |
| EVAL-03 | 收起、被挡住、换模式/地图时按键；关闭程序后按键再打开 | 收起和被挡时照计；计数落在当前模式；关闭期间的按键不补 |
| EVAL-04 | 在干净的 Windows 上装、开、卸 | 记下 SmartScreen、Windows Defender 的实际表现；不需要改系统安全设置 |
| EVAL-05 | 管理员程序、UAC 弹窗、锁屏下按键 | 记录哪些收不到，写进"不支持"清单 |

如果用户仍想先看 A：先只做一个连接小实验——本机起一个最小 WebSocket 服务，从 GitHub Pages 正式地址用当前版 Chrome、Edge、Firefox 去连，再把标签页放后台 30 分钟。通过标准是三个浏览器都能连、只出现一次正常的权限确认、后台 30 分钟不断。不通过就不必再往 A 投入。

## 4. 需要策划另定的

- **软件模拟的输入算不算**：Windows 层面，自动连点器、宏工具发出的按键和真实按键看起来差不多（Raw Input 能区分一部分）。现在网页只认 `isTrusted`，这类输入在网页里是算的。桌面版要不要排除，需要定（不影响路线选择）。
- Q23（后台输入默认开还是关）和 Q24（PC 版说明文案）仍等答复，这两条在 B 里直接用得上。
