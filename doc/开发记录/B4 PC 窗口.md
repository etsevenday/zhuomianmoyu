# B4 PC 窗口

日期：2026-11-17　|　依据：`doc/策划案/透明界面与跨专题同步 v0.2/` 01 §2—§5、05 §2—§8（TECH-01—09、TECH-20—26）、§6.1（Q6/Q7 答复）。
用例：[B4 PC 窗口](<../测试用例/B4 PC 窗口.md>)。技术路线用户 2026-11-17 定：Electron 外壳装网页版同一份 Blazor 包，界面和 C# 内核不分叉；以后要手做动画特效时再考虑迁 Godot。

本批只做窗口。不做：PC 全局后台输入（策划案待定，提了 Q23）、Steam 真实联机、安装包和签名。

## 1. 工程映射

| 规则 | 实现 |
| --- | --- |
| 外壳（`pc/`） | `src/main.js` 主进程：透明无框窗口（`transparent`、`frame:false`、不让系统改大小），单实例；网页包挂在自定义协议 `moyu://app/` 下（标成 standard + secure，localStorage、IndexedDB、Web Locks 都能用，存档跟着数据目录走）。`src/preload.js` 给页面一个 `window.moyuPc`，页面据此判断是不是 PC。`build-web.mjs` 把 `web/Moyu.Web` 发布成 Release 包放到 `pc/.web`（不入库），构建号写"PC 本地 · 提交号" |
| 窗口尺寸计算（05 §6.1） | `pc/src/layout.js` 纯函数：基准宽 B=min(W,16H/9)，显示 max(400, min(sB, 工作区能放下的最大 16:9))；s 只在玩家缩放成功松手时改；位置存工作区里的相对位置，放不下的轴平移回可用范围、没有余量就留在边界；窗口归属按和各屏重叠面积最大的那块。验收脚本直接调用它 |
| 窗口设置 | 数据目录 `window.json`：`{ version, s, displayId, rx, ry }`，和玩法存档（IndexedDB）、网页偏好（localStorage）分开。读到坏的字段逐项回落（s→1/4、位置→工作区右下、屏→主屏），不碰玩法存档 |
| 页面里的 PC 模式 | `FakeDesktop.razor` 在 PC 下只画小窗（或收起头像），填满整个窗口，没有假桌面、记事本、任务栏和角落说明；`PetWindow` 按窗口宽缩放设计稿（`--pc-scale`），右下角多一个 14×14 的缩放热区。渲染完把收起、置顶、穿透同步给外壳 |
| 分区穿透（TECH-03、UI-11） | 窗口平时忽略鼠标、只转发移动（`setIgnoreMouseEvents(true, {forward:true})`）；页面在每次指针移动时看指针下面是不是画出来的实体（和网页版同一套 `pointer-events` 规则），是才让窗口接住。点完按钮后指针不动也再判断一次，面板关后不留热区。穿透关时整窗接住。拖动、缩放中不切换，免得半路丢指针 |
| 拖窗（TECH-04、TECH-20） | 和网页版同一套手势（按住角色、水面、头像，超过 5 像素算拖），只是位移按屏幕坐标算、改成移动原生窗口；拖动中大小不变，松手按落在的屏重算尺寸并记相对位置。拖动和缩放都在小窗里，不算捕鱼输入 |
| 右下角缩放（Q6） | 左上角不动，宽度按指针沿对角线的位移变，锁 16:9；不小于 400×225，不大于工作区能放下的最大 16:9，右下角不出工作区。拖动中按 Esc 或指针被取消都回到拖动前尺寸、偏好不变；成功松手才用算出来的宽度（未取整）换成新的 s |
| 收起（UI-09） | 窗口缩成头像（直径为展开高的 1/4），放在展开窗口左下角色处（和网页 `DesktopLayout` 同一算法）；拖头像不恢复，松手按头像位置反推展开位置；单击恢复 |
| 置顶 | 设置里的"置顶"在 PC 版真的改窗口置顶，默认开（沿用 B2 默认） |
| 关闭（01 §5） | 关闭 = 退出程序：先存窗口偏好和玩法档，再退出。Alt+F4、任务栏关闭也走这条，页面 3 秒没回应就直接退。PC 版没有"已关闭"状态，下次启动小窗照常打开 |
| 显示器变化（TECH-09、TECH-24） | 监听显示器增减和分辨率、缩放变化：原屏还在用原屏，否则主屏；按 s 重算，按相对位置放回可用范围；不改玩家偏好 |
| 单实例 | 再启动一次不开第二个窗口，把原窗口显示出来 |
| 输入 | PC 版窗口里收到的键鼠都是对小窗的操作，一律不算工作输入（`play.js`）；全局后台输入另批（Q23）。所以 PC 版目前路亚、摸鱼不涨，手竿照真实时间计 |

## 2. 取舍

- **取整**：算法里一直用小数，只在交给 Electron 时取整；s 用缩放时算出来的宽度定，不用取整后的窗口宽，避免一次次缩放累计偏差。
- **右下角不出工作区**：05 §6.1 只说上限是"工作区内能容纳的最大 16:9"。开发方另外要求缩放时右下角不出工作区（左上角不动），贴着屏右边时就放不大，要先往里拖一点。
- **松手时整窗夹进工作区**：和网页版拖窗一样，松手后整窗放回可用工作区，不允许拖到一半出屏。
- **网页专属说明**：TXT-SET-004（"网页演示开关，不会改变系统置顶……"）和 TXT-SET-005（"仅统计本页面内……"）在 PC 版说得不对，PC 版先不显示，等文案（Q24）。网页版照旧。
- **缩放提示**：只用缩放光标，不加文字（05 §6.1 文字交文案定，Q24 一并问）。

## 3. 测试模式

`MOYU_TEST=1` 时外壳打开 `?dev=1` 开发入口和 `window.moyuPc.test`（读窗口矩形、穿透、置顶、焦点、设置文件；换虚构显示器；按位移拖窗），并且：

- 用 `MOYU_FAKE_DISPLAYS` 给的虚构显示器代替真实的，换屏、拔屏、改分辨率都靠换这张表；
- 系统鼠标一律不进窗口。调试时发现窗口挪到测试机真实光标底下时，系统会补发鼠标移动，混进 CDP 模拟的拖动，窗口就跟着真实光标跳。CDP 的指针事件直接送进页面，不受影响；穿透状态照样按页面要求记着。真实系统穿透由人工 B4-M2 看；
- 关掉 Chromium 的原生遮挡计算（虚构屏上的窗口多半在真实屏幕外）。

另外两个 CDP 的限制写在脚本里：合成的指针事件落到视口外就不送（真实鼠标有系统捕获），所以缩放分小步走、指针始终留在窗口里；合成事件的屏幕坐标按页面记着的窗口位置算，所以拖窗每步等窗口到位、页面的 `screenX` 也对上了再走下一步。

## 4. 运行

```bash
cd pc
npm install
npm run build:web
npm start
```

`npm install` 后如果 `node_modules/electron/dist` 不存在（npm 11 没跑 Electron 的下载脚本），补一步 `node node_modules/electron/install.js`。
