## 2. 取舍

- **加入时的房间构成**：01 §2 只要求"由明确标注的模拟成员担任房主"。为了不用额外操作就能演示到迁移和成员权限，加入时房里先有好友1（房主）和好友2，本人第三个进。
- **模拟控制作用在选中成员上**：01 §2 说具体排版由开发定。模拟动作、收获、断线都对房间页里选中的那位做；没选中时这几个按钮不能点。"移除模拟好友"不选也能用（移除最后加入的普通模拟成员），房主要走用"模拟房主离开"。
- **让模拟房主切图的入口**：演示控制里用三张地图的名字做按钮（地图名沿用地图页的），定稿里没有单独的按钮名，不另写新词。
- **迁移中点地图行**：普通成员的地图行禁用；迁移中没有房主，地图行仍可点，点了提示 TXT-ROOM-027（B3-26 要验"点了提示且不变"）。
- **好友卡片盖在面板上**：演示控制在房间页里，收获时房间页多半开着；卡片不接指针，所以盖在面板上面不影响点按钮。本人的鱼获卡片仍只在没开面板时出现（B1 规则不变）。
- **开发入口**：`moyuDev.roomReplay()` 把上一条好友收获消息原样再送一次、再送一条旧代次的，返回被接受的条数（应为 0）；`moyuDev.room(动作, 成员)` 做界面上那一刻点不到的演示（收起时让好友收获、查看鱼缸时让对方断线或结束模拟），和演示控制走同一套方法。都只在 `?dev=1` 下有。
- **角落试玩说明不改**：TXT-SET-009"……好友联机与更多鱼缸尚未开放。"照旧显示；真实好友联机确实还没开，本机模拟在房间页另有 TXT-ROOM-002 说明。
- **房间面板排版**：房间页加宽到 1520×676（左边成员列表，右边演示控制和说明），离开、结束模拟放在右栏底部。

## 4. 测试结果

推送前对本地 Release 包（e0d7b31+改动）：内核 NUnit 160/160；`b3.mjs --release` 18/18；回归 `b2.mjs --release` 37/37（B2-29 按本批改了预期，标"B3 改"）、`b1.mjs --release` 62/62、`b0.mjs --release` 47/47。

变异测试 `--since:origin/main` 首轮 150 个、幸存 9，按准则 §5 逐条处理：

| 位置 | 变异 | 处理 |
| --- | --- | --- |
| `RoomMember` 人物/竿/手套/场景默认值 ×4 | 默认串改成空串 | 补用例 B3-14：新成员默认是基础外观、没设背景缸 |
| `Room.Host` | `HostId == null` 分支改成永远不走 | 等价（没人的编号是 null，`Find(null)` 本来就落空），删掉这个分支，`Find` 收 `string?` |
| `Room.Map` | 去掉 `?? 默认图` | 等价：MapId 只在构造和 SwitchMap 里赋值，两处都核过是目录里的图；标 `Stryker disable once` 并写明原因 |
| `CompleteMigration` 的 `First` | 改成 `FirstOrDefault` | 等价：迁移中一定还有成员（最后一人离开时房间直接结束）；标 `Stryker disable once` 并写明原因 |
| `SetMode` 的 `Spot == null` | 改成 `!=` | 用例不够严：本人恰好在自动安排的首选位，重排回原地看不出来。B3-10 改成先把本人挪到 x=900 再在岸边两种模式之间换，落点必须不动 |
| `ViewTank` 的 `Ended ?` | 改成永远不走 | 补断言：房间结束后成员还在名单里，查看也要给"已离开"，不给旧快照 |

处理后 144 个、幸存 0（1 个超时：`SpotPlanner` 循环 `i++` 改 `i--` 成了死循环，算抓住）。改完 Room.cs 后 b3 Release 重跑 18/18。

开发版首跑两条失败都是脚本前置问题（静音偏好、前面用例已解锁记录），详见[用例表](<../测试用例/B3 同图房间.md>)运行记录和失败归类。
