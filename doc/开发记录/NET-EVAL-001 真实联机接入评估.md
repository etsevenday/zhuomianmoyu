# NET-EVAL-001 真实联机接入评估：PC 版怎么接 Steam 房间

日期：2026-11-18　|　发起：用户"真实联机写评估"

依据：[房间规则 ROOM-001](<../策划案/同图房间 v0.1/01 房间规则与模拟陪伴.md>)、[B3 交接与验收](<../策划案/同图房间 v0.1/02 B3交接与验收.md>)（NET-01—05）、[B3 房间文案](<../策划案/文案交接 v0.1/04 B3房间文案定稿.md>)（TXT-ROOM-038—048 已是 PC 真实房间的句子）、现有代码（`src/Core/Rooms/Room.cs` 房间状态机、`pc/` Electron 外壳和采集程序）。
§1—§7 写于实验前：库的能力来自文档和代码清单，标了"待实测"的在 §6 第一步的小实验里验证，结果见 §8（2026-11-18 已做）。

## 1. 结论

**推荐：外壳旁边加一个 C# 的 Steam 小程序（和后台输入的采集程序同一个做法），用 Steamworks.NET 接 Steam；房间规则继续由页面里现有的房间状态机执行，Steam 只负责"谁在房间里、谁是房主、把消息送到"。开发和测试先用 Steam 公用测试 ID 480，不用等自己的 App ID。**

| | 结论 |
| --- | --- |
| 要不要先有 App ID | 不用。开发、内部测试用 480；上架前换成自己的（改一个配置），申请可以并行办 |
| 难度 | 中。难点不在 Steam，在"多台电脑同时操作时规则还对"：抢位、换房主、断线 |
| 工作量（开发方估计） | 先做 1 次小实验（过了才继续），之后约 2 个批次；真人多号测试另算 |
| 最大风险 | 测试条件：真 Steam 联机要 2—4 个 Steam 账号、2—4 台电脑同时在线，CI 上跑不了 |
| 需要先定 | 用户：谁来办 App ID、准备几个测试账号和电脑；策划：没开 Steam 时怎么办、邀请入口放哪（§7） |

## 2. 现在已经有什么

- **房间规则已写成代码**：`Room.cs` 是纯逻辑的状态机：4 人上限、只有房主能切图、选位放不下留原位、断线立即移除、换房主时代次加 1、旧代次消息不认、好友收获事件去重、只读看鱼缸。B3 的网页模拟就是它在跑，内核有单元测试。真实联机要做的是把"模拟成员的操作"换成"网络另一头真人的操作"，规则本身不用重写。
- **PC 真实房间的文案已定稿**：创建、邀请已发出、正在加入、已加入、邀请失效、版本不一致、创建/加入失败、断线重连、房间已结束（TXT-ROOM-038—048）。
- **外壳带一个 C# 子程序的做法已经跑通**：后台输入的采集程序就是外壳启动的独立 exe，用标准输入输出和外壳通信，打包时自带运行时（B5、B6）。Steam 小程序照抄这个结构。

## 3. Steam 怎么接：三种做法

Steam 的接口是 C/C++ 的，外壳是 Electron（Node），中间要一层绑定。

| | A：steamworks.js（Node 插件，在外壳主进程里调） | B：steamworks-ffi-node（Node 直接调 Steam 的 dll） | **C：C# 小程序 + Steamworks.NET（推荐）** |
| --- | --- | --- | --- |
| 覆盖 | 建房、加入、房间数据、成员列表、打开 Steam 邀请窗口；网络只有 Valve 已标记废弃的旧 P2P 接口；**没有**直接邀请某个好友、没有成员各自的数据 | 文档列了房间和新的网络接口 | Steam 全部接口一对一包了一层，房间、好友列表、直接邀请、成员数据、新网络接口都有 |
| 维护 | 主分支最后一次提交 2025-09，一年多没动，单人维护 | 0.x 版本，单人维护，较新 | 持续维护，2025 年底还在跟新的 Steam SDK，有 .NET 8 包 |
| 和现有工程 | 外壳里加原生模块，要处理 Electron 版本兼容 | 同左 | 和采集程序同一套：C#、自带运行时、外壳拉起、标准输入输出通信；开发方现有的 C# 测试方式都能用 |
| 缺点 | 缺接口要自己补原生代码 | 年轻，出问题只能自己查 | 多一个进程（约 30 MB）；Steam 叠加层（Shift+Tab）不会画在我们的小窗上（见 §5） |

C 多一个进程，但换来的是接口齐全、库在维护、和现有采集程序同一种做法。

## 4. 消息怎么走、规则怎么落

**谁是房主**：直接用 Steam 房间（Lobby）的"房间所有者"。Steam 后台保证任何时刻只有一个所有者；所有者退出或掉线时，Steam 自动把所有者交给房间里的另一个人（**待实测**：交接的时机和通知顺序）。这正好对上 Q18 的"唯一房主、自动迁移"，不用自己做选举。

> 现在 `Room.cs` 迁移时按"加入最早的人"选新房主。改成"Steam 指定谁就是谁"，内核这处要跟着改（01 §4.4 写明新房主的选择顺序归开发实现，不改玩家看到的结果）。

**消息分三类**：

| 内容 | 走哪 | 说明 |
| --- | --- | --- |
| 房间快照：版本、地图、代次、房主主题、房主背景鱼缸 | Steam 房间数据（只有房主能写，Steam 自动同步给所有人） | 新加入、重连的人一进来就能读到当前快照，不用找房主要 |
| 每个人自己的：显示名、模式、人物/竿/手套、自己设的背景鱼缸 | Steam 成员数据（每人只能写自己的） | 只读看好友鱼缸（Q21）就读这里 |
| 选位请求和确认、切图、好友收获展示、动作 | Steam 网络消息（经 Steam 中继转发，不暴露玩家 IP） | 请求和收获用可靠发送；动作合并成每秒一两次、用不可靠发送，丢了也不影响规则 |

**每条规则怎么保证**：

| 规则 | 做法 |
| --- | --- |
| 4 人（Q15） | Steam 房间建成 4 人上限，第 5 人 Steam 直接拒绝 → "邀请已失效，或房间已结束"或满员说明 |
| 位置只由房主确认（09、NET-02） | 成员发选位请求给房主，房主页面里的 `Room.Place` 判定后广播结果；请求带地图和代次，旧的一律不认，两个人同时抢同一处只会有一个成功 |
| 个人收益各算各的（Q16 推荐 A） | 每人自己的鱼、金币、存档照旧在本机；收获只广播"展示用"的鱼图、名字、体长，接收方不发奖 |
| 断线 0 秒释放（Q19、NET-03） | Steam 通知某成员离开或掉线，房主立即 `Room.Remove`；重进按新加入。单次丢包不算断线，由 Steam 的连接状态判定 |
| 换房主（Q18、NET-03/04） | Steam 换了所有者 → 新房主代次加 1、写新快照、接管选位确认；旧房主回来是普通成员。迁移中拒绝选位、切图 |
| 迁移失败 | Steam 房间没了或超时：回单机、留在当前图、个人档不动，显示 TXT-ROOM-048 等现成句子 |
| 版本不一致 | 房间数据里写游戏版本，加入时对不上就离开，显示 TXT-ROOM-044 |
| 邀请（NET-01） | 游戏里列出在线的 Steam 好友，点"邀请"直接发 Steam 邀请；好友没开游戏时 Steam 会提示并启动游戏、带上房间号自动加入（**待实测**）。邀请发出只显示"已发出邀请"，对方真进来才显示"已加入" |

**页面和 Steam 小程序怎么连**：小程序 ↔（标准输入输出）↔ 外壳主进程 ↔（预加载脚本，和采集程序同一条路）↔ 页面。页面里只认一个"联机传输"接口，网页版接"本机模拟"，PC 版接"Steam"，测试时接"本机回环"（§6）。

## 5. 风险和已知限制

- **Steam 叠加层**：Steam 的 Shift+Tab 叠加层是注入到游戏画面里的，对透明、置顶的小窗不可靠，所以邀请不靠它，用游戏内的好友列表（需要策划定位置，§7 Q27）。
- **没开 Steam**：PC 版现在不需要 Steam 也能玩。接入后 Steam 没运行、没登录时，单机照常，只有房间入口不能用（需要策划和文案定说法，§7 Q26）。
- **480 是全世界共用的**：别人的测试房间也在里面。我们只用"仅好友"房间，加自己的标记过滤，不做公开房间列表。用 480 时好友那边看到的游戏名是"Spacewar"，正式 App ID 换上后才是"桌面摸鱼"。
- **消息频率**：Steam 对房间数据的更新频率有限制（**待实测**），所以快照只在变了的时候写，动作走网络消息。
- **好友展示无法核实**：Q16 选了各算各的，好友那边显示的鱼是对方客户端说的，本机核实不了。这是 Q16 推荐时就说明过的取舍，不影响本人资产。
- **打包**：要带上 Steam 的 `steam_api64.dll`；开发时放 `steam_appid.txt`（480）。包体增加约 30 MB。

## 6. 怎么做、怎么测

1. **小实验（约半个批次，过了才继续）**：Steam 小程序用 480 在两台电脑、两个 Steam 账号间做一遍：建仅好友房间、游戏内邀请、对方从未启动的状态被拉起加入、房间数据和成员数据同步、网络消息往返（量延迟、看频率限制）、房主退出后 Steam 换所有者的时机。结果写成实验记录，不行就回来改方案。
2. **联机协议 + 本机多开（1 个批次）**：页面里加"联机传输"接口；房主权威、选位请求/确认、快照、代次、迁移按 §4 做；内核 `Room` 迁移改成"外部指定新房主"。再做一个**不需要 Steam 的本机回环传输**，测试模式下允许同一台电脑开 4 个外壳（现在是单实例，测试模式另开数据目录绕开），用脚本模拟 4 个人同时抢位、断线、换房主。NET-02—05 的规则部分在这里**自动测**，CI 上也能跑。
3. **接上 Steam（1 个批次）**：Steam 传输、游戏内好友列表和邀请、各种失败状态接上 TXT-ROOM-038—048。NET-01 和"真实断线、真实换房主"只能真人多号测（人工用例，像 #9 那样发给测试的人）。
4. **换正式 App ID（上架前，很小）**：改 `steam_appid` 和房间标记，重跑一遍人工用例。

CI 上不能登录 Steam，所以 Steam 本身的那部分只能人工测；规则对不对靠第 2 步的本机多开自动测，这部分占 NET 验收的大头。

## 7. 需要先定的

**用户定**（不挡开工，但第 1 步小实验前要有测试条件）：

- 测试账号和电脑：至少 2 个 Steam 账号、2 台能同时开的电脑（或一台电脑 + 一个虚拟机）；测 4 人房要 4 个。
- 自己的 App ID 谁去办、什么时候办：Steam Direct 每个游戏交 100 美元（游戏收入到 1000 美元后在分成里退回），要注册 Steamworks 合作伙伴、填税务和银行信息、过身份验证，一般要几天到几周。上架前办好就行，和开发并行。

**策划定**（第 3 步前要答，开发方先按建议做）：

- **Q26 没开 Steam 或没登录时 PC 版怎样**：A. 单机照常玩，只有房间入口提示"需要先启动并登录 Steam"（开发方建议）；B. 必须开着 Steam 才能启动。选 A 要文案补一句提示。
- **Q27 邀请好友的入口**：A. 房间面板里列出在线的 Steam 好友，每人一个"邀请"按钮（开发方建议：不依赖叠加层）；B. 只靠玩家在 Steam 好友列表里右键"邀请加入游戏"。选 A 要定好友列表的排版和几句文案（列表标题、在线/游戏中状态、没有在线好友时的说明）。

## 8. 小实验结果（2026-11-18）

程序：`tools/steam-spike/`（[README](<../../tools/steam-spike/README.md>)），加入方的包发在 Releases `steam-spike-1`，经 [etsevenday/zhuomianmoyu#11](https://github.com/etsevenday/zhuomianmoyu/issues/11) 交策划在另一台电脑上跑。两台电脑不在同一局域网，两个互为好友的 Steam 账号（开发方当房主），全程走 Steam 中继。

| 项目 | 结果 |
| --- | --- |
| 建仅好友房间（4 人） | 通过，约 0.3 秒 |
| 邀请到对方进房（对方已开着程序） | 通过，863 毫秒（其中对方进房本身 295 毫秒）；对方程序收到邀请自动进房，不用在 Steam 里点 |
| 房间数据进房就能读到 | 通过（标记、版本、代次、房主的模式都对） |
| 成员数据同步 | 通过，对方改自己的模式后 423 毫秒房主读到 |
| 非房主写房间数据 | 没生效（房主读不到），**但对方那边 `SetLobbyData` 返回了 true** |
| 网络消息往返 30 次 | 30/30，最短 140、中位 145、最长 152 毫秒 |
| 不可靠消息 1 秒连发 100 条 | 100/100 |
| 房间数据 2 秒连改 20 次 | 对方收到 20 次更新，最后的值对；这个频率没碰到限制 |
| 房间聊天连发 10 条 | 10/10 |
| 房主退出后换所有者 | 通过：对方在房主说要走后约 1.2 秒收到"离开"通知，这时所有者已经是自己，随即写入新代次成功；旧房主回来读到所有者是对方、代次 2 |
| 旧房主回来后写房间数据 | **没过预期**：`SetLobbyData` 返回了 true（预期 false）。结合"非房主写房间数据"一行，非房主写一律返回 true、但不生效；旧房主这次写有没有生效没量，按那一行推断也不生效 |

结论：方案 B（Steam 房间 + 网络消息）可行，§4 的做法不用改；"待实测"的交接时机、数据频率都已量过。两点落到第 2、3 步：

- **能不能写房间数据看 `GetLobbyOwner`，不看 `SetLobbyData` 的返回值**（上面两行：非房主写也返回 true，只是不生效）；快照带代次，收到比自己已知代次旧的快照就丢掉，旧房主即使写进去也不会把房间带回旧状态。
- 房主离开约 1 秒后接手。"正在切换房主…"（TXT-ROOM-029）只会显示一秒多，不用做长等待。

没测到的：对方**没开程序时**点邀请被拉起加入（480 会启动 Valve 的 Spacewar，换自己的 App ID 才能测，留到第 4 步）；4 人房（只有 2 个账号）；真实掉线（拔网线，不是正常退出），留给第 3 步人工用例。两边的结果文件（房主、加入方各一份）对得上，上表已按两份合并。
