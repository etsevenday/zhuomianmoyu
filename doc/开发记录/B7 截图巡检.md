# B7 截图巡检

日期：2026-11-18　|　依据：用户 2026-11-18 定"定期让 AI 看画面，按每批看一次"。没有策划案。
用例：[B7 截图巡检](<../测试用例/B7 截图巡检.md>)。第一次巡检：[B7 画面巡检](<../画面巡检/B7.md>)。

## 1. 为什么

验收脚本查的是数字和状态：计数对不对、存档存没存、面板开没开。字被截断、按钮叠在一起、弹窗被底栏盖住，脚本不会报错，真人试玩又不一定每个角落都点到。所以加一套固定截图，由开发方每批看一次。

## 2. 做了什么

| 部分 | 实现 |
| --- | --- |
| 截图脚本（`tools/verify/shots.mjs`） | 网页（无头浏览器，不占鼠标键盘）：视口 1600×900、1920×1080 下截全清单 25 个画面，2560×1440 下截 6 个；先截空档，再用开发入口加金币、放鱼，真按键钓出一条鱼截出鱼卡片，真卖鱼截卖出提示、账本，打开存档失败后再卖截保存失败提示。PC：用测试模式外壳在 1280×720、1920×1080 两种主屏下截首次后台输入提示、常态、设置、输入说明展开、收起头像（全新数据目录，只起采集程序，不发输入） |
| 自动检测 | 每张截图前在页面里查：可见元素出了小窗、文字被截断（内容比框大又不让滚）、同一行的按钮标签互相压住。只记下来给看图时对照，不判失败 |
| 输出 | `shots/<尺寸>/NN-画面.png`、四宫格总览 `sheets/NN.png`（每格下面写画面名和检测结果，PC 图垫棋盘格看透明）、`shots.json`、`shots-results.json` |
| CI | `pc` 任务发布之后，解开刚打好的包、用包里的 exe 截一套，存成 `shots` 附件。`if: always()` + `continue-on-error`：验收没过也截（看坏在哪），截图出错不挡发布 |
| 看图 | 开发方每批推送前跑一次、看总览和有检测结果的单张，写 `doc/画面巡检/<批次>.md` |

## 3. 取舍

- **每批看一次，不是每次推送都看**：每次推送 CI 都截，存着；看图要花时间，一批看一次够了，需要时拿两次运行的附件对比。
- **检测不判失败**：出界、截断这些规则有误报（比如行高比字小 1 像素也算截断），判失败就会为了变绿去调规则。真问题看图确认后，照准则补成具体的脚本检查再修。
- **小窗整体缩放**：三档尺寸排版一样，所以大尺寸只截几张；问题多半跟内容长短有关（总数位数、模式文字长度），截图时要放进有数据的状态。

## 4. 测试结果

本地 Release 包 3a64b1a + 开发版外壳：`shots.mjs --release` 5/5（76 张）。调试中 4 次中断都是脚本自己的错，见用例表。照 CI 那一步用打好的包再跑一次也是 5/5。

上线后：CI 08ece3f 全过，发布后截图那步 5/5，`shots` 附件齐全（B7-05）。改了 CI 流程，按约定对线上 PC 包跑 `b6.mjs --online` 8/8；网页构建号 08ece3f、载入和存档正常。

第一次看图发现 9 条（底栏挤压、"更多"弹窗被盖、PC 首次提示文字出条、皮肤卡片挤、几处贴边），见 [B7 画面巡检](<../画面巡检/B7.md>)。这批只做巡检工具和记录，界面没改；修的时候照准则先补用例。
