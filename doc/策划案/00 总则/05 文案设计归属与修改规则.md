# 文案设计归属与修改规则

生效日期：2026-11-16（建仓起）。沿用《适者生存》中文案策划 shioko0315 设定的规则：所有文案相关内容由文案策划负责，其他策划和开发不得擅自修改其设计；文案有问题，必须先向 shioko0315 提问，由本人确定。

## 适用范围

本规则覆盖世界观、正典设定、全部人物小传、人物关系、故事大纲、主支线剧情、任务叙事、对白、旁白、档案，以及物品、技能、敌人、地点的命名与描述、界面提示和其他玩家可见文案。相同内容存于策划案、配置、代码、网页或其他载体时，均适用本规则。

其他策划、开发及代表这些岗位工作的自动化工具，不得自行改写、删减、扩写、替换、重新定稿或改变文案设计的含义、口吻与呈现文本；发现错字、表述不清、设定冲突或实现限制，也须先提问，不能以修错、精简、补全或实现同步为由直接修改。

## 职责边界

| 负责人 | 决策内容 |
| --- | --- |
| 文案策划 shioko0315 | 世界观、人物、剧情等文案设计；已定含义下的名称、标题、描述、帮助、提示、日志、对白、角色口吻、标点、术语统一及逐字定稿。 |
| 策划 dotpad1994 | 玩法机制、UI 布局与流程、显示哪些字段／放在哪／何时出现、数值及其计算、开放条件与权限等非文案设计。 |
| 开发方 etsevenday | 提供真实现状、按已定规则实现与验证、维护待确认问题与 GitHub issue 指派；原样接入已确认文案。 |

"写在哪里／何时显示／显示哪些事实或控件"属于 UI 设计；"同一已定位置里的句子怎么说、术语怎么统一"属于文案。一个问题同时包含两者时，分成"Qn-设计""Qn-文案"两个子项分别交两方。文案发现缺少真实规则时，只把具体缺口交回策划，不自行补数值或虚构玩法。

## 发现问题后的处理

1. 保留原文，指出具体文件、章节或文本 ID，并引用有问题的原句。
2. 向 shioko0315 说明问题和具体触发情境；必要时给出候选改法及其影响。候选内容必须标为建议，不能写入正式文案或上线文本冒充定稿。
3. 等待 shioko0315 明确裁定。未答复、未读、待定，以及其他岗位的同意，都不能视为文案策划确认。
4. 按 shioko0315 确定的内容落实；开发可以原样接入已确认的文本，但不得在接入时再自行改写。若仍需调整，重新提问。保留原有文本 ID、历史记录与开发方维护的【实现同步】记录。

开发方在 GitHub 上给文案问题开 issue，打"待文案确认"标签并指派 shioko0315；混合问题的设计部分仍打"待策划确认"指派 dotpad1994。

后续授权以 shioko0315 本人明确给出的具体范围为准，不能从一次确认推定其他文案也获准修改。

这是项目协作与审核规则；它本身不改变 GitHub 的账号权限或分支保护设置。
