# 房间规则与模拟陪伴

系统编号：ROOM-001；单案修订：0.1；更新日期：2026-11-17。
规则状态：基础设计，Q14—Q22已获用户答复；本轮网页仅本机模拟，真实Steam连接及网络验收留PC。本文不是联机功能已实现的证据。

## 1. 目标、职责与边界

让最多4名成员在同图显示角色、独立模式动作和收获，保留连续岸边/浅水、自动安排、单击选位/按住拖窗、允许靠近、放不下保留原位。空间唯一规则继续由[多人选位09](<../透明界面与跨专题同步 v0.2/09 同图多人选位与表现.md>)维护；本文件维护房间权限、生命周期、共同外观与只读展示。

Q14选B：网页不接真实消息服务、不创建可供真实好友加入的链接、不接Steam账号；由本机生成明确标注的模拟好友，先检查多人构图、模式、动作、收获归属与权限状态。PC首发仍保留Steam开房/邀请，真正并发、断线、重连、房主迁移须跨真实客户端验证，不能用模拟通过替代。

模拟成员的鱼获、装备和鱼缸是展示样本，不初始化另一份可交易个人档，不给本人发鱼/金币、不推进本人计数/记录/未读，也不能冒充真实好友已经联网。

结构化参数见[房间规则JSON](<assets/房间规则 v0.1.json>)；它只在策划资料中，不是运行配置。

## 2. 玩家流程

右上房间 → 查看“本机模拟”说明 → 创建模拟房间或加入模拟房间 → 自动跟随共享地图并安排落点 → 添加模拟成员（含本人最多4人） → 同图观察/选位/切模式 → 主动离开 → 单机留在房间最后地图，恢复本人原有场景主题/背景选择。

创建时本人为房主，房间初始地图为本人当前地图。加入模拟房间时由明确标注的模拟成员担任房主，便于验证成员权限；房间地图、成员和样本由演示控制提供，不能假装收到真实邀请。模拟入口均为管理输入，不加捕鱼计数。

模拟控制须能触发成员加入/离开、不同模式的动作/收获、普通成员断线/重新加入、房主离开/迁移、查看收藏及关闭演示；具体排版、演示动作节奏与样本配色由开发实现。无需要单独控制的演示项可以合并入口，但不能缺少各计划验收的可触发路径。未处于房间时不存在成员位置占用或房间切图权限。

## 3. 对象与主数据

| 对象 | 语义字段／范围 |
| --- | --- |
| 房间 | 房间ID、运行种类（模拟／PC真实）、规则版本、代次、房主ID、当前地图/地图修订、成员快照；上限4人含房主 |
| 成员 | 稳定成员ID、加入次序、本人/模拟标识、当前模式、确认位置、连接状态、人物/鱼竿/手套装备标识 |
| 共享画面 | 当前房主的场景主题、房主当前设为背景的鱼缸快照及其修订；无选择时为未设背景 |
| 只读鱼缸 | 所有者ID、容器展示标识、鱼种/外形/体长、快照修订与可用状态；不含金币、鱼篓、输入记录或其他容器 |
| 表现事件 | 事件ID、房间代次、获得者/动作成员、模式、鱼图/名称/体长、展示修订；无给接收者发奖权限 |
| 个人档 | 仍按既有输入、周期、手竿、鱼获、金币、收藏与外观合同；共同画面不覆盖本人装备/背景设置 |

位置坐标仍为地图空间，窗口的桌面位置/DPI不进入房间坐标。快照和表现只带展示必需数据，不传按键内容或逐键时间线。

## 4. 规则与结算

### 4.1 人数和位置

Q15选4人（含房主），第5人不得加入或挤走现有成员；模拟入口也遵守4人上限。三图都要验证4人全岸钓、全摸鱼、混合模式，不能因满员改为独立钓台、编号座位或把角色缩到不可辨。

房主端统一确认位置，占用/请求去重及地图/房间代次遵循09。普通成员只能为自己选位，无法移动其他成员。模拟可以通过同一个房间状态机验证逻辑结果，真实跨端同时抢位仍是PC验收。

### 4.2 个人收益（Q16用户交开发方定）

【交开发方定】推荐沿用开发方选项A：每个玩家自己计算和保存输入、出鱼、金币、收藏与记录，房间仅展示；房主只确认公共地图和位置，不代存其他玩家资产。这样进入/退出/迁移/断线不会转移个人收益权，也不能验证好友展示的鱼一定真实捕获。本项记录为用户授权开发决定，不能写成用户直接选了A。

开发按此推荐完成本轮架构选择，无需再就相同选择询问策划；无论内部实现如何，既有捕获/售价/计时数值、个人资产连续性、远端表现不能向本人发奖，以及原子保存/不重复结算合同都须保持。网页版模拟成员不参与实际收益结算。

### 4.3 共享地图（Q17）

- 进入房间跟随房间当前地图；本人原图的主动次数/手竿时间按现有规则暂停保留。接收房间快照并确认切图后才使用新地图，不能提前假切成功。
- 只有当前房主能切图，成功后全房一起切；普通成员可查看当前图但切图控件不可用，并说明仅房主可切。每人保持自己的当前模式，旧图进度冻结，新图使用对应模式已有进度，重新自动安排位置。
- 切换生效前先按旧图结算已符合条件的个人输入/手竿时间；切换后不把旧图临界鱼改成新图鱼。旧地图的落点和迟到动作不得覆盖新图。
- 主动离开后留在房间最后一张已确认地图，不返回进房前地图；不清该图或其他图的个人进度。离房恢复本人自己的主题和背景偏好，公共展示不永久改写本档。

### 4.4 房主离开、断线与迁移（Q18/Q19）

Q18选迁移，取代“首版房主离开直接解散”的候选。房主正常退出或确认断线时先移除该成员、释放其占用，再由仍在房间的有效成员自动接管。迁移不换公共地图，不清其他成员的确认落点和个人资产；新房主接管公共位置确认并发布新代次/当前快照，其他人恢复后继续。旧房主回来按普通新加入处理，不夺回房主身份。

新房主选择顺序、握手/超时/故障检测属于开发实现：须得到唯一房主和唯一当前代次，不能让两个客户端都确认公共位置；不能无限停在迁移中，须有可取消/离开的入口及明确失败结果。沿用旧技术原文的失败退路：迁移确定失败则回本地单机、留当前已确认地图、保留个人进度/资产与重新加入入口；只有空房或确认结束才显示房间已结束。网页只能验证模拟状态流转，不能宣称验证了Steam迁移。

Q19选断线即移除：普通成员一旦被连接机制确认断线，立即从房间角色/成员/占用中移除，保留时间0秒，不显示60秒保座倒计时。单次丢包不直接等于确认断线，检测阈值由开发实现。重新加入按新加入自动安排，不保证原位；若满4人可拒绝，不驱逐新占位者。主动退出同样立即释放。

房主确认断线也不保留旧位置，但按Q18触发迁移而非直接解散。只剩1名有效成员时该成员可成为房主继续；无人剩余则房间结束。迁移期间暂不接受新的公共切图/选位确认，旧请求应失败或在新快照后重提，不能在两个代次双成功；个人玩法不因迁移获得额外奖励或被回滚。

### 4.5 角色外观、场景主题、底层鱼缸（Q20）

每名成员显示其本人装备的人物、鱼竿和手套。房间场景主题和底层鱼缸全房使用当前房主的选择；其余成员自己的选择仍保存在本档，离房恢复，不因观看获得房主的皮肤或鱼。

房主改变主题、背景选择，或展示缸入鱼/取回时，以新快照更新公共画面；无背景选择时不画公共鱼缸，设为空缸时只画框架。主机迁移成功后跟随新房主当前主题/背景，不继续冒充旧房主仍在主持。主题/鱼缸只改画面，不改变共享地图、鱼池、节点、位置、容量与收益。

公共鱼缸沿用核心03：原1600×900场景内最底层，钓鱼场景/成员/UI在其上覆盖，向内框架、透明留白、缸鱼统一尺度及裁切、不接指针。默认没设背景的房主不会因建房被强制设置鱼缸。

### 4.6 好友收获与只读收藏（Q21）

好友抓到鱼时，在对应好友落点播放收获动作，头顶显示鱼图、名称、体长卡片，并有克制提示音，受本人静音开关控制。复用本人卡片4000毫秒展示和高频合并规则，但不抢焦点、不展开面板、不增加本人的鱼篓/金币/输入/新鱼数/捕获记录。本人手竿产生的常规鱼仍不冒充主动节点保底。

普通好友输入动作继续合并降噪、不逐键发声；提示音只随新的有效收获展示触发，不因重复消息/恢复快照重放。多个好友同刻收获要能分清归属，可合并声音避免刺耳，具体音色和节奏由开发实现。收起时不强行恢复，不补播过期卡片/声音；静音后动作和卡片照常。

首版可从成员列表只读查看任一在房成员当前设为背景鱼缸的内容；这与主场景统一显示房主鱼缸是两个入口。只展示该成员当前选择的容器、鱼的外形/名称/体长及占用，不展示其全部收藏、鱼篓、金币、输入明细或未选择的鱼缸。进入房间即按此规则共享该展示快照，房间说明须告知范围。

查看页没有取回、出售、导入本人收藏、设为本人背景或装备权限；看见好友的未知鱼不解锁本人记录。对方未设背景则说明未设置，空缸说明空；对方换缸/入鱼/取回则按新修订更新，对方离开/断线后不再把旧快照当在线可用。浏览对象来自房主还是普通成员均不改变公共场景选择。模拟数据始终标模拟，退出演示不留下可变现副本。

## 5. UI与输入

房间面板显示运行种类、人数n/4、当前房主/地图、成员及各自模式/角色外观、模拟标识、查看鱼缸入口；普通成员地图页说明权限。共享主题和鱼缸旁提供“跟随房主”语义，离房恢复本人偏好。

网页不得显示成功复制真实邀请链接、真实好友已加入或Steam连接成功；无真实连接的PC专属入口可隐藏，说明使用模拟。未来PC真实创建/邀请/握手/加入成功/满员/失效/版本不一致/迁移/重连按实际状态显示，发送邀请不等于已加入。

所有房间控件、成员查看、复制/邀请（PC未来）、模拟控制及查看收藏均是管理输入，不计捕鱼；模拟动作不等于本人键鼠输入。按本次Q22授权接入[联机文案定稿](<../文案交接 v0.1/04 B3房间文案定稿.md>)，复用B0/B1已有位置提示，不自行再写一套占位话。

## 6. 状态、事务与存档

模拟房间为临时展示状态，刷新后回到单人、清模拟成员/占用，不把演示房间伪装成持续在线服务；个人资产与显示偏好按既有存档恢复。仅公共展示时临时使用房主主题/缸，不覆盖本人原偏好。

PC真实重连先确认同一房间是否存在、版本与容量，再拿当前房主/地图/成员/主题/缸快照；Q19已移除的成员重新安排位置，不重放断线期间历史动作/收获声音。原房间失效、满员或版本不一致时保持可用单机状态，显示实际原因，可退出或重试，不回滚个人存档。

所有位置/表现/只读收藏消息按房间、成员、地图/房间代次、快照修订及事件ID校验；离开成员、旧房主旧代次、旧地图数据不得覆盖当前快照。公共画面消息没有资产写入权限；重复收获展示不重复播放和发奖。网络连接的身份/API选型与同步频率由开发实现，本案不指定引擎插件或付费后端。
