## 完整原文

<!-- 原文开始 -->
这版讨论稿建议采用“捕获 → 暂存与整理 → 出售或收藏 → 扩充展示空间、抽取外观 → 继续捕获”的循环。鱼缸容量限制展示数量；捕获后的鱼即使暂时放不下，也应被完整保存。

文中所有新增价格、容量、概率和流程均为【建议草案】，供后续讨论。

**一、已定边界与本稿假设**

【用户已定】

- 鱼获可以出售换取游戏币，也可以收藏，作为游戏背景欣赏。
- 游戏币可以用于抽取人物、鱼竿、摸鱼手套、场景皮肤，以及购买更多鱼缸。
- 鱼有大小，收藏展示需要体现个体尺寸，并有记录页面。
- 主动路亚、主动下水摸鱼、按时间获得鱼获的手竿模式均需覆盖。
- 保留用户基线：路亚500次输入50%、1000次必上钩；摸鱼200次输入20%、2000次必摸中；手竿30分钟一条。

【建议草案】

- 只有一种游戏币；出售与抽取均不引入付费货币或交易市场。
- 皮肤只改变外观，不改变捕获率、保底进度、鱼价或鱼缸容量。
- 首版鱼的体长在捕获时确定，收藏期间保持不变。“实时显示尺寸”指随时准确呈现这个体长，不代表鱼会随时间长大。
- 每条鱼都是独立个体，同种、同尺寸的两条鱼也拥有不同编号。

【待确认】

已收藏鱼能否重新出售、容量单位、判定与重置规则、模式并行和离线收益，均未由用户确定。下文提供推荐方案，并明确经济样例采用的假设。

**二、物品和货币怎样流转**

【建议草案】鱼获采用以下状态，任何时刻只处于其中一个：

| 状态 | 玩家看到的内容 | 可执行动作 |
|---|---|---|
| 待整理鱼获 | 刚捕获、尚未安排去向的鱼 | 放入背包、直接收藏、出售 |
| 背包个体 | 已选择保留的鱼 | 锁定、收藏、出售 |
| 收藏个体 | 已放入某个鱼缸或水族馆的鱼 | 查看、移动、移回背包 |
| 待完成出售 | 出售后的30秒撤销期 | 撤销 |
| 已出售个体 | 鱼已离开持有列表，仅留历史记录 | 查看捕获和出售记录 |

流程建议如下：

1. **捕获先保存，再播放反馈。** 捕获成功时先生成个体记录，之后显示动画；关闭界面、切换背景不影响鱼的归属。
2. **保留进入背包。** 首版可提供30条的背包整理容量，支持按地图、鱼种、体长和估值排序。
3. **收藏是移动同一个体。** 放入鱼缸后，背包中的该鱼消失；移动鱼缸也只是更换位置，不复制鱼。
4. **收藏默认锁定。** 建议允许日后出售，但需先移出鱼缸并明确解锁；批量出售跳过锁定个体。
5. **出售有30秒撤销期。** 鱼先进入待完成出售状态，金额显示为“待到账”，暂不可花费；到期后正式到账。这仍是同一种游戏币。
6. **撤销必须能成功恢复归属。** 优先回到背包；背包已满则回到待整理区，不要求玩家先腾位置。
7. **鱼缸回收是收起展示容器。** 空缸可以收回容器列表，再次放出；有鱼时不能直接收起，需先搬鱼。首版暂不设置鱼缸折价卖回。

防止重复出售的底层约束是：**同一个体只能完成一次有效出售，同一出售请求重试也只能到账一次。** 正式出售同时完成“个体离开持有状态”和“游戏币入账”，历史记录不能再次作为可售物品。

【建议草案】背包满时，新增鱼进入**持久待整理区**：

- 不自动出售、不自动替换旧鱼、不设置领取倒计时。
- 支持直接出售，或腾出位置后收纳。
- 手竿连续获得的鱼也进入这里，允许批量整理。
- 待整理区允许长期保留，因此背包容量主要是整理提示；真正需要购买扩展的是展示空间。

这一取舍会弱化背包容量的限制作用，但能避免轻量挂机游戏把玩家的收益变成清理负担。

**三、鱼缸容量采用什么单位**

【建议草案】三种方案比较：

| 方案 | 规则示例 | 优点 | 代价 |
|---|---|---|---|
| 按条数 | 每缸最多8条，大小均占1条 | 清楚、好操作，大鱼收藏成本可预测 | 小鱼与大鱼负担相同，拥挤程度不完全一致 |
| 按体长负担 | 各鱼体长之和不得超过某值 | 尺寸与容量直接关联 | 大鱼可能成为收藏惩罚，移动时需要反复计算 |
| 按体型槽位 | 小/中/大鱼占1/2/4槽 | 比体长总和直观，也能区别大小 | 分档边界容易产生“只长一点却多占槽”的落差 |

**首版推荐按条数，拥挤另作视觉提示。**

演示配置可采用：初始鱼缸8条；第一个额外鱼缸400币、第二个800币，均增加8条展示容量。具体价格需结合鱼获速度验证。

不建议首版无限递增扩容价格。后续大缸可以按新增条数与主题价值定价，避免收藏越久，容量越难负担。

大鱼依然按真实体长展示。若合法鱼种的最大尺寸超出默认缸可表现范围，需要地图与鱼种专题提供最大体长，以便确定默认缸的世界尺寸和镜头范围。

**四、游戏币来源与消耗**

【建议草案】

| 类型 | 项目 | 规则 |
|---|---|---|
| 主要来源 | 出售主动路亚鱼获 | 按个体估值入账 |
| 主要来源 | 出售主动摸鱼鱼获 | 使用同一估值体系，具体鱼种分布由玩法与地图决定 |
| 主要来源 | 出售手竿鱼获 | 同样逐条生成个体，不直接发币 |
| 次要返还 | 抽到已拥有皮肤 | 按重复处理规则返还少量游戏币 |
| 容量消耗 | 购买鱼缸、水族馆容器 | 明示新增容量，直接购买 |
| 外观消耗 | 抽取四类皮肤 | 单抽价格明确，展示概率与保底进度 |

首版建议不设置喂食费、鱼缸维护费或鱼死亡损失。收藏可以长期作为背景存在，不要求玩家定期回来看护。

鱼获在出售和收藏之间形成机会成本：留下喜欢的大鱼，就暂时少获得一笔游戏币；未来允许移出出售时，这个选择仍可调整。

**五、鱼获估值公式**

【建议草案】先用容易解释的公式：

\[
出售价格=\operatorname{四舍五入}\left[
鱼种基础价\times稀有度系数\times
\operatorname{限制}\left((体长/参考体长)^{1.2},\,0.5,\,2.5\right)
\right]
\]

- **鱼种基础价**：体现鱼种价值，需与捕获频率一起确定。
- **稀有度系数**：演示取普通1、稀有2.5、珍稀6。
- **尺寸系数**：同种鱼越大越贵；上下限避免极端尺寸导致经济失控。
- **地图不额外直接乘价**：地图差异先通过鱼种构成体现，避免重复叠加奖励。

例如，一条参考体长30厘米、基础价40币、稀有度系数2.5的鱼，实际体长60厘米：

\[
40\times2.5\times2^{1.2}\approx230币
\]

这里的鱼种、稀有度和参数均为演示值。

图鉴纪录不因出售而消失。“曾经捕获最大个体”和“当前拥有最大个体”分别记录；纪录本身首版不额外发币，避免重复刷纪录奖励影响经济。

**六、皮肤池、重复与保底**

【建议草案】首版只设一个常驻池，覆盖人物、鱼竿、摸鱼手套、场景四类。界面展示全部外观，允许按类别预览。

演示池可采用16款：每类2款基础、1款稀有、1款珍藏。这里只描述池结构，不代表美术数量已经确定。

| 档位 | 基础概率 | 档内选择 |
|---|---:|---|
| 基础 | 75% | 优先从该档未拥有外观中等概率抽取 |
| 稀有 | 20% | 同上 |
| 珍藏 | 5% | 同上 |

配套规则建议：

- 单抽240游戏币；十连仅方便操作，价格与逐次抽取相同。
- 连续19次未获得珍藏，第20次必得珍藏；提前获得则重置计数。
- 保底跨退出与更新保留，不按天清零。
- 选中的档位仍有未拥有外观时，不出重复。
- 该档位全部拥有后，抽中该档改为返还48币，即单抽价的20%。结果明确提示这是重复返还。
- 全池收集完成后，抽取按钮改为“已集齐”，停止扣币。
- 珍藏档集齐后，关闭珍藏保底并提示原因；基础档位概率仍公示，玩家可判断是否继续补齐其他档位。

概率公示需同时显示：基础档位概率、当前保底进度、下一抽是否保底、各档剩余未拥有数量、具体物品当前获得概率、重复返还规则。不能只写“珍藏5%”却隐藏档内选择方式。

这一方案不会保证玩家首次抽取就拿到偏好的类别。若后续反馈集中在“只想要场景却一直出装备外观”，可再讨论分类池；首版先避免多套池与保底并存。

**七、首日与一周经济演示**

以下均为【建议草案：情景推演】，不能作为已定收益承诺。

先明确判定歧义：

| 解释 | 经济后果 |
|---|---|
| 每次输入均有基础捕获概率，再叠加节点与保底 | 必须补充基础概率；收益会高于只在节点判定的模型 |
| 路亚500次判一次；摸鱼每200次判一次；分别在1000/2000次保底 | 收益可计算，适合作为本稿演示假设 |
| 摸鱼只在200次判一次，失败后等2000次保底 | 摸鱼平均收益明显更低 |

本稿推荐用第二种解释做经济试算，供玩法专题确认。演示另假设：

- 成功后该模式计数清零；不同主动模式分别保存计数。
- 只统计有效输入，自动重复按键如何认定尚待确认。
- 每天主动路亚150分钟，平均每分钟20次有效输入，共3000次。
- 另有120分钟在线手竿，获得4条；主动与手竿分时进行。
- 不计算离线收益。
- 鱼获平均估值假设为80币；这需要未来的鱼种分布验证。
- 约75%的鱼出售，25%留下收藏。

按这个解释：

- 路亚每条鱼平均需要：\(500×50\%+1000×50\%=750\)次输入。
- 摸鱼每200次判定20%，第10次强制成功，平均约892.6次输入一条。
- 如果摸鱼只在200次判定一次、之后等2000次保底，平均则为1640次输入一条。

因此，3000次有效输入的长期平均产出约为路亚4条、重复判定摸鱼3.36条。实际短期结果还受起始保底进度影响。

为展示钱如何花，下面采用**首日实际获得8条、一周累计56条**的演示账本；这是一套可能发生的结果，接近上述长期速率，不是掉落保证。

| 项目 | 首日 | 一周累计 |
|---|---:|---:|
| 捕获 | 8条 | 56条 |
| 出售 | 6条 | 42条 |
| 保留 | 2条 | 14条 |
| 出售收入，按均价80币 | 480币 | 3360币 |
| 抽取皮肤 | 1次，240币 | 累计10次，2400币 |
| 购买额外鱼缸 | 暂不购买 | 1个，400币 |
| 剩余游戏币 | 240币 | 560币 |
| 展示容量 | 8条 | 16条 |

这里没有计入重复皮肤返还，实际余额可能更高。10抽也尚未触发20抽硬保底，不能保证一周内得到珍藏外观。

这套演示支持“第一天获得一次外观变化、一周扩充一缸并保留约14条鱼”。如果真实输入速度、出售比例或平均鱼价明显不同，需要重新评估240币单抽与400币扩容价格。

**八、收藏室作为背景的产品流程**

【建议草案】收藏室入口分为“管理收藏”和“设为背景”。

1. **选择容器。** 缩略图显示名称、占用条数、代表鱼；鱼缸偏近景，水族馆偏大空间展示，两者使用同一批个体与容量规则。
2. **放鱼。** 从背包或待整理区选鱼，看到体长、估值及目标容器余量，预览后确认。
3. **移动。** 从当前容器选择鱼，再选择目标容器。目标无余量时不改变原位置，并提供等量交换入口。
4. **设为背景。** 选择整个容器作为当前游戏背景；切换背景不移动鱼，也不产生新的容量。
5. **扩容。** 在容器列表中直接购买，购买前明确显示新增条数、价格和预览。
6. **查看图鉴。** 从鱼或记录页进入，查看鱼种、捕获地图、日期、体长、个人最大纪录及当前拥有数量。

尺寸展示采用同一场景内统一的厘米尺度，鱼的长宽比例保持原样。窗口缩小为屏幕一半或四分之一时，整体画面统一缩放；不把每条鱼分别缩到差不多大。小窗口中点击鱼可查看准确厘米数。

拥挤反馈独立于硬容量：即使未到8条，多条大鱼也可以显示“空间较拥挤”，并建议换缸或调整展示。首版拥挤只影响构图提示，不暗中扣收益、缩小鱼或使鱼死亡。

**九、两个完整操作例子**

【建议草案】**例子一：抓到大鱼，选择收藏。**

玩家捕获一条60厘米的鱼。系统先保存个体，再显示“大于你此前纪录”的反馈，同时展示体长、估值230币和“收藏 / 保留 / 出售”。

玩家选择收藏，进入容器选择页：A缸已有5/8条，预览中这条鱼明显大于其他小鱼。确认后，它从待整理区移动到A缸，容量变为6/8，并默认锁定。

玩家把A缸设为背景，鱼按60厘米对应的比例游动；图鉴更新最大纪录。日后若想出售，需要先移出并解锁。出售后，60厘米的捕获纪录仍然保留。

【建议草案】**例子二：背包与鱼缸都满，再次捕获。**

玩家背包30/30，所有鱼缸均满，又捕获一条鱼。

系统照常保存并显示“已保存在待整理区，背包和展示空间已满”。玩家可以：

- 直接出售新鱼；
- 出售背包旧鱼，再收纳新鱼；
- 用新鱼替换鱼缸内某条鱼，被换出的鱼进入背包或待整理区；
- 购买新鱼缸后放入；
- 关闭面板，稍后整理。

若玩家直接出售，进入30秒撤销期；此时反悔，鱼回到待整理区。若玩家关闭游戏，重新进入仍能找到这条鱼及其处理状态。

**十、跨专题最小字段接口**

【建议草案】这里只提出接口需求，不代表其他专题已接受。

| 接口对象 | 最小字段或约束 |
|---|---|
| 捕获事件 | 唯一事件编号、玩家编号、来源模式、地图、捕获时间；重复投递不得重复生成鱼 |
| 鱼获个体 | 唯一个体编号、鱼种、体长及单位、稀有度、归属玩家、当前状态、位置、锁定标记 |
| 鱼种配置 | 参考体长、允许体长范围、基础价、展示资源；需支持统一尺寸比例 |
| 出售事务 | 事务编号、个体编号、估值版本及金额、撤销截止时间、完成状态 |
| 游戏币账本 | 流水编号、来源事务、变动金额、时间；同一来源不能重复入账 |
| 展示容器 | 容器编号、拥有者、容量、世界尺寸、已放入个体、当前背景标记 |
| 皮肤抽取 | 池版本、外观编号与类别、拥有记录、当前保底进度、抽取结果及返还金额 |
| 图鉴记录 | 鱼种、首次捕获、最大体长及对应个体、累计捕获数；与当前持有状态分开 |
| 好友房间展示 | 当前背景及公开展示的鱼；他人查看不获得移动、出售权限 |

**十一、风险、验证指标与关键待确认项**

【建议草案】优先验证四件事：

| 风险 | 验证指标 |
|---|---|
| 重复捕获事件、重复点击出售造成资产异常 | 同一个体重复出售与重复到账均为0；断线重进后归属可核对 |
| 满容量造成丢失或整理压力 | 满容量鱼获保留率100%；观察待整理数量和单次整理耗时 |
| 输入差异让经济速度悬殊 | 按有效输入速度分组统计每小时鱼获、收入、首次扩容与首次抽取时间 |
| 大鱼收藏吃亏，或背景看不清大小 | 观察大鱼收藏率、移出率、拥挤提示率，以及玩家能否辨认尺寸差异 |

另需观察收藏比例与币的积累速度：若大部分鱼都出售、容量长期空置，收藏吸引力可能不足；若玩家积币却不愿抽取，应先检查外观吸引力、重复体验和价格，而不是增加维护费。

【待确认】下一轮优先只需敲定四组问题：

1. **计数解释：** 是否采用节点判定；摸鱼是否每200次重复判定；成功后如何重置、切模式是否保留。
2. **收藏退出：** 是否允许已收藏鱼移出后出售；推荐允许，并默认锁定。
3. **容量与尺寸：** 是否采用按条数容量；首版是否保持捕获体长、不做随时间成长。
4. **收益与外观边界：** 模式是否并行、是否有离线收益，以及皮肤是否全部只改变外观。

这些确定后，才能把本稿的演示价格进一步收敛成可验证的首版经济表。
