**《一起摸鱼 bongo fishing》总策划 V0.1｜讨论稿**

本稿仅讨论游戏定位、核心体验与首版范围。下文的【建议草案】均可调整，不代表用户已定，也不代表其他专题已经通过。

**一、定位与玩家价值**

【建议草案】一句话定位：

**一款陪你使用电脑的轻量联机钓鱼游戏：日常输入变成可爱动作，闲置时间也能收获鱼，把工作与休息间的小收获养成自己的水族背景。**

核心体验应按以下顺序取舍：

1. **陪伴感**：正常使用电脑时，屏幕边缘有角色回应，反馈可爱且不抢注意力。
2. **积累感**：输入和等待都能逐渐变成看得见的鱼获。
3. **表达感**：玩家用角色、装备外观和收藏背景表达喜好。
4. **共处感**：和 Steam 好友待在同一个房间，各自做事，偶尔分享收获。

推荐目标场景：

| 使用场景 | 玩家当下的主要任务 | 游戏应该提供的体验 |
|---|---|---|
| 写作、编程、办公 | 注意力在其他软件 | 输入触发轻反馈，收获暂存，不要求立即处理 |
| 看视频、阅读、开会 | 输入少或没有输入 | 手竿持续提供等待中的陪伴 |
| 短暂休息 | 愿意主动看游戏 | 整理鱼获、布置鱼缸、换装、切换地图 |
| 和朋友一起使用电脑 | 各自忙自己的事 | 看见彼此角色和重要收获，无需组队任务维系关系 |

【建议草案】首版不以冲榜、操作技巧或高强度刷取作为主要吸引力。玩家即使不追求效率，也应能理解自己正在积累什么。

**二、用户已定的骨架与推荐核心循环**

【用户已定】

- 玩家可以开房间，邀请 Steam 好友加入。
- 采用卷轴式画面方向，界面可以只占屏幕下半部或下方四分之一。
- 键盘输入或鼠标点击可以触发路亚拉竿、下水摸鱼动作。
- 路亚基线：500 次输入咬钩一次，成功率 50%；1000 次输入必上钩一次，成功率 100%。
- 下水摸鱼基线：200 次输入获得一次判定，成功率 20%；2000 次输入必摸中一次。
- 手竿基线：不操作电脑，按时间自动获得鱼获，30 分钟一条。
- 鱼获可出售换游戏币，用于抽取人物、鱼竿、摸鱼手套、场景等皮肤；也可放入收藏室欣赏。
- 可以购买更多鱼缸，扩展收藏容量。
- 鱼有大小，收藏展示和记录页面需要体现大小。
- 首发设定三个地图，不同地图有不同鱼种。

【建议草案】核心循环：

**正常使用电脑 → 输入触发角色动作 → 累积主动玩法进度 → 获得鱼获 → 暂存待处理 → 出售或收藏 → 外观与容量成长 → 更喜欢自己的陪伴画面。**

手竿作为另一条入口接入：

**在线等待 → 到达手竿时间 → 获得鱼获 → 接入相同的出售、收藏与成长循环。**

这里增加“暂存待处理”，目的是让玩家获得鱼后继续工作，等休息时再决定去向。暂存方式和容量属于待设计内容。

两条成长线分别承担不同价值：

- **出售 → 游戏币 → 皮肤抽取**：让重复鱼获也有用途，逐渐改变陪伴画面。
- **收藏 → 展示空间逐渐充实 → 购买更多鱼缸**：让喜欢的鱼和有纪念意义的尺寸留下来。

【建议草案】鱼获先作为独立个体存在，同一条鱼只能处于一个归属位置；收藏后的鱼允许取出并出售，出售后移除，避免同一条鱼重复兑现。此项仍待确认。

**三、正常工作时，反馈应怎样发生**

【建议草案】采用三层反馈，按注意力成本递增：

| 层级 | 触发 | 推荐表现 |
|---|---|---|
| 动作反馈 | 每次有效输入 | 拉竿、划水、爪子动作等局部反馈；高频输入时合并动画表现 |
| 收获反馈 | 获得鱼获 | 游戏区域内出现简短提示，随后进入待处理列表 |
| 主动查看 | 玩家打开游戏面板 | 查看鱼种、尺寸、记录、出售及收藏操作 |

关键约束：

- **有效输入计数与动画播放分开**：合并动画不应偷偷减少已经认可的有效输入。
- 默认关闭声音，不弹系统通知，不抢窗口焦点。
- 收获提示不需要点击确认；关闭提示不会损失鱼获。
- 半屏、四分之一屏是可选展示档位，保留清楚的收起入口。
- 推荐提供穿透与可交互状态切换，避免遮挡其他软件操作。
- 默认只突出本人的收获；好友普通动作降低表现频率，防止房间人数放大干扰。
- 输入反馈只需要事件与计数，不需要记录用户输入的文字内容。

验收重点是：**玩家连续正常工作时，不需要为了维持游戏进度而反复切回游戏。**

**四、三种玩法与其他系统如何共同服务体验**

| 系统 | 【建议草案】体验职责 | 首版需要避免的问题 |
|---|---|---|
| 主动路亚 | 提供容易理解的“输入—拉竿—期待收获”关系 | 为了更快出鱼，诱导玩家持续无意义敲击 |
| 主动下水摸鱼 | 用不同动作、角色姿态和收获节奏形成选择 | 只换动画，没有可感知的体验差异 |
| 手竿 | 覆盖阅读、看视频等少输入场景 | 每到时间就强制领取，打断当前任务 |
| 好友房间 | 提供一起待着的氛围与偶发分享 | 房主或队友缺席导致个人进度停摆 |
| 收藏室 | 将积累转化为长期可见的成果 | 只有列表数字，看不出鱼的大小差别 |
| 皮肤 | 让重复鱼获持续产生外观目标 | 外观附带效率差异，压过个人偏好 |
| 三张地图 | 提供景观变化与不同鱼种的期待 | 首版过早加入复杂解锁、任务和旅行成本 |

【建议草案】主动路亚与下水摸鱼互斥选择；手竿可与其中一种主动玩法并行。这样既保留明确的当前动作，也覆盖输入少的时候。并行会增加总产出，经济专题必须据此评估，不能按单模式产出定价。

【建议草案】好友房间首版共享场景与角色表现，鱼获、计数、货币和收藏各自归属。暂不加入交易、共同资金或协作增益。

**五、玩家旅程**

**首次 10 分钟**

【建议草案】目标是让玩家明白“怎样陪伴我”和“收获之后有什么意义”，不要求十分钟内完成全部成长。

- **进入后约 1 分钟**：看到角色、当前地图、主动模式和手竿计时；直接展示尺寸切换与收起入口。
- **随后约 2 分钟**：通过少量实际输入体验动作反馈，切换一次路亚与下水摸鱼。
- **中间约 4 分钟**：引导玩家回到原本使用的软件，观察游戏能否安静陪伴。
- **最后约 3 分钟**：查看进度，浏览收藏室、记录页和皮肤预览，理解鱼获的两个去向。

不能用用户基线承诺“首次十分钟必定自然获得鱼”。若需要展示完整流程，推荐提供**明确标注的教学演示鱼**，只用于预览收藏和出售流程，不进入正式资产或经济。

**日常一小时**

【建议草案】目标是形成“开始时设置、过程中陪伴、结束时整理”的习惯。

- 开始时选择地图与主动模式，按需加入好友房间。
- 正常使用电脑，输入驱动动作，手竿计时。
- 鱼获出现时自动暂存，玩家可继续工作。
- 在休息或结束时集中整理：保留喜欢的鱼，出售其余鱼，查看新外观与鱼缸目标。

按“完整在线计时、手竿连续运行”的推荐假设，一小时应覆盖两个 30 分钟周期；实际结算边界、暂停与计时保存规则由玩法专题明确。主动鱼获数量暂不作承诺。

**长期一周**

【建议草案】目标是让玩家开始形成个人偏好：

- 找到最喜欢的展示尺寸、主动模式和地图。
- 收藏室出现有区别的鱼，能直观看出个体大小。
- 有理由保留新鱼，也有理由出售重复鱼。
- 形成一个可见的短期目标，例如某个外观或新增鱼缸。
- 与好友形成“上线后一起待着”的使用方式。

首版不依赖每日签到、连续在线奖励或周任务制造回访。具体一周能获得多少鱼、抽取几次、扩容几次，需要等待概率和经济方案合稿后再确定。

**六、推荐版本范围与验收条件**

下表中的新增数量均为【建议草案】，用于控制规模；三个首发地图属于【用户已定】。

| 阶段 | 推荐范围 | 可观察的验收条件 |
|---|---|---|
| **首个可玩原型** | 1 张测试地图、3 种测试鱼；三种玩法的最简闭环；基础输入反馈；鱼获暂存、出售、收藏；1 个鱼缸及尺寸展示；2 人房间验证。皮肤只做预览和一次流程验证 | 能从输入走到真实鱼获，再走到出售或收藏；无人输入时手竿能按基线完成一个周期；两名玩家可共处且各自进度独立；连续使用其他软件时不抢焦点、不强制处理提示 |
| **MVP：最小可发布版本** | 完整覆盖三个地图；建议共 12 种鱼、每图 4 种；三种玩法正式规则；Steam 好友邀请；建议房间上限 4 人；收藏与尺寸记录；游戏币、基础皮肤抽取、鱼缸购买；半屏和四分之一屏；存档与必要设置 | 三地图鱼种差异可验证；所有用户基线及保底规则能复现；关闭重开后资产与进度符合规则；收藏、出售、扩容无重复资产或丢失；好友加入退出不改变个人收益；一小时工作场景无需强制切回游戏 |
| **后续版本** | 优先完善鱼缸布置、收藏展示、房间表现和外观内容；根据实际使用反馈决定是否增加鱼种、地图或社交功能 | 新内容不提高默认打扰程度；收藏展示更容易体现个人偏好；玩家能找到新增目标且理解获得途径；每项扩展均有明确使用需求或反馈依据 |

【建议草案】原型中的计数与计时可使用测试加速工具验证，但必须与正式规则区分；保留真实 30 分钟周期和正常输入节奏的体验验证。

MVP 推荐暂缓：

- 玩家交易、共享经济、排行榜及协作加成。
- 复杂养殖、生病死亡、喂食维护、繁殖等系统。
- 多层任务、体力、装备数值养成和复杂地图解锁。
- 大规模家具建造及精细水族馆经营。

这些都不是当前已定核心循环的必要条件。MVP 应先证明：**陪伴本身舒服，获得鱼后愿意留下来整理和展示。**

**七、影响全局的待确认项：共 8 项**

| 【待确认】 | 【建议草案】推荐默认值 | 原因与影响 |
|---|---|---|
| **1. “每次输入有概率”与指定次数判定如何统一？** | 优先采用指定次数节点判定；普通输入负责动作与进度。500/1000、200/2000及相应成功率全部保留，成功后开始新周期；中间节点由玩法专题明确 | 另一选项是每次输入独立抽取、次数节点追加判定与保底，会带来更多鱼获和提示。两者会显著改变节奏与经济，不能混用。具体概率计算交给玩法专题 |
| **2. 三种模式是否并行，切换如何处理进度？** | 两种主动玩法互斥，手竿并行；按“地图×主动模式”分别保留计数。手竿保持单条计时线，周期开始时绑定产出地图 | 避免切换损失，也避免把快完成的周期临时转到另一地图。需要界面清楚提示当前计数与本轮手竿归属 |
| **3. 什么输入有效，长按和自动重复怎么算？** | 只累计玩家实际产生的按下或点击事件；长按产生的系统自动重复不累计；多设备和极高频事件由玩法专题给出统一约束 | 决定正常电脑使用与重复按键行为之间的产出差距；应避免迫使玩家改变正常操作习惯 |
| **4. 后台、退出与离线是否产鱼？** | 游戏运行且功能开启时，后台可累计；退出后暂停手竿并保存已完成时间，离线不新增收益 | 保持首版规则清楚。若加入离线收益，需要另定时间上限、领取方式和经济影响 |
| **5. 联机共享到什么程度、支持多少人？** | MVP 建议 4 人；共享场景、角色与重要收获提示，资产和进度独立；房主离开后保留个人游玩能力 | 先验证陪伴价值，控制同步复杂度；人数仍为建议 |
| **6. 鱼获归属、暂存与鱼缸容量怎样定义？** | 单鱼单归属；收藏鱼可取出出售；鱼缸采用固定展示槽位，不按体积计算；待处理鱼获与展示容量分开 | 容易理解和核对；鱼的大小先影响视觉与记录，避免大鱼占满空间。具体槽位和暂存上限另定 |
| **7. 皮肤是否影响效率，抽取覆盖哪些内容？** | 皮肤只改外观；首版提供小规模人物、鱼竿、手套、场景外观池；重复处理、抽取概率与价格交经济专题 | 保持玩家按喜好选择；抽取规则影响成长速度，需要与总产出一起定 |
| **8. 窗口默认怎样展示，允许多大打扰？** | 默认下方四分之一屏，可切半屏；静音、不抢焦点、不强制领取；提供收起和交互状态切换 | 让正常工作始终是主任务。窗口占位、遮挡与穿透的具体实现需要界面及技术专题评估 |

其中第 1 项是节奏判断的前置条件：在概率模型确认前，不能可靠承诺“几分钟一条鱼”“一小时能抽几次”或“一周能扩几次鱼缸”。

**八、另外五个专题需要提交的决策与接口**

以下按合稿所需的五类专题划分，不代表其他聊天已经采用这些分工或结论。

| 专题 | 应提交的关键决策 | 总策划需要的字段或约束 |
|---|---|---|
| **玩法与概率** | 有效输入、判定节点、成功与失败、保底、重置、切换、计时、离线规则；三模式在典型使用情况下的节奏 | `模式`、`有效输入定义`、`计数归属`、`判定节点`、`成功率`、`保底条件`、`重置规则`、`计时状态`；低/中/高输入强度下的鱼获与提示频率 |
| **地图与鱼类内容** | 三地图定位、鱼种差异、尺寸范围、产出限制；稀有度是否必要 | `地图ID`、`鱼种ID`、`可用玩法`、`尺寸范围及单位`、`外观资源需求`、`展示比例规则`、`产出条件` |
| **经济、收藏与外观成长** | 出售价值、鱼缸购买、容量、抽取和重复处理；收藏鱼取出与出售流程 | `鱼个体ID`、`当前位置`、`出售价值规则`、`鱼缸容量`、`扩容价格`、`皮肤ID及适用对象`、`抽取成本与规则`；代表性一小时和一周成长结果 |

**九、合稿时统一的术语**

【建议草案】

- **输入事件／有效输入**：前者是检测到的操作，后者是按规则可以计数的操作。
- **动作反馈／获得判定**：角色动一下，不等于进行一次获得鱼的抽取。
- **咬钩／捕获成功**：需要玩法专题确定是否为同一结算结果，避免重复套用成功率。
- **计数周期／保底**：统一周期起止、保底触发与成功后的重置含义。
- **鱼种／鱼个体**：鱼种定义内容；鱼个体拥有自己的尺寸与归属。
- **待处理鱼获／收藏室／鱼缸**：分别表示收获整理入口、整体收藏展示系统、具体容量容器。
- **手竿／在线等待／离线收益**：三个概念分别使用，不能互相替代。
- **地图／场景皮肤**：地图决定产出；场景皮肤默认改变外观。
- **人物皮肤／装备皮肤**：首版按外观理解，避免“人物”被误读为独立能力角色。
- **房间共享表现／个人进度**：共同看见的内容与个人持有的资产明确区分。
