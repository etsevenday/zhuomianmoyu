## 1. 目标、职责与边界

实现小型透明16:9窗口、分区域命中、角色/水面拖动和可恢复操作；保留Steam开房邀请。PNG有alpha只证明参考图透明，不证明Windows穿透、焦点、DPI或Steam组合已通过。

本次不编写/修改代码、运行原型或部署。Godot、Unity、Electron、Raw Input、SQLite及Steam传输路线仍是技术候选，不能因UI选定视为已选栈。

## 2. 状态与流程

| 状态 | 要求 |
| --- | --- |
| 日常显示 | 透明负空间、实体场景和独立UI；反馈不主动抢焦点 |
| 管理面板 | 用户主动打开；实体面板能操作，外围命中按穿透开关 |
| 拖动 | 仅角色/水面启动；由按下至释放/取消整体隔离于捕鱼 |
| 收起/恢复 | 保留明确恢复入口，不因后台鱼获/成员变化强行展开 |
| 关闭 | 按已选资产政策保存；退出计时/收益政策仍待玩法 |
| 穿透开启 | 默认；透明留白及独立控件之间的空隙可点击下层 |
| 穿透关闭 | 用户可选；留白仍视觉透明，但不再承诺下层命中；角色/水面与设置入口仍可用 |

窗口位置可自由放置；多屏/分辨率变化后保证能找回，不自动把它固定回底部或调整其他应用窗口。

## 3. 对象与接口

窗口比例/物理尺寸依据、显示器与相对位置、DPI/布局缩放、穿透状态、置顶/收起/焦点状态；UI/拖动/透明热区；当前模式；本地管理事件与后台输入去重标识；房间连接状态、成员摘要与表现事件ID。

输入层只需工作操作的动作资格和计数，不需把文字内容发给玩法或网络；原始键标识过滤的范围与有效输入政策另由玩法/隐私说明确认。

## 4. 命中、焦点与模式约束

- 视觉alpha和指针热区分开，不能用整图矩形、整个顶右控件包围框或AI边缘阈值代替最终热区。
- 透明留白默认穿透；手动关穿透只改变命中，不填回白色背景，不丢失重新开启入口。
- UI和展开菜单优先接收自身操作；不能同时开始拖动。
- 拖动的按下、移动、释放、取消，以及随后可能产生的点击都不能补记捕鱼输入。
- 后台/前台通道统一去重；被UI消费的操作不能从后台再次记入。
- 当前模式唯一。切换时非当前模式不再累计，旧动画或网络消息不拥有收益权限。
- 鱼获、好友进出、网络重连、收起状态下事件不得主动激活工作焦点。
- 置顶与后台输入开关与穿透分开；不能因为窗口透明推定采集权限；PC后台输入的默认开来自用户Q23明确选择，网页仍只作演示。

这些是接口与实现必须达到的结果；不在此承诺某个原生窗口标志即可解决全部行为。

## 5. Steam房间与UI

Steam开房与好友邀请仍为PC需求；本轮网页仅模拟。Q14—Q22已定4人、房主切图/自动迁移、断线即释放、各人装备/房主主题与缸、好友收获及只读当前背景缸；个人收益架构交开发方定，推荐各端个人结算。离线身份和平台连接适配仍在PC阶段完成，具体规则唯一引用房间正文。

房间面板需接收创建/邀请/加入/离开/失败状态和权限，不把发出邀请显示为好友已经加入。是否允许在房间里改地图由权限接口提供；无权限时不能只改本地选中项伪造公共场景成功。

好友普通动作合并表现、不逐键发声；只传展示所需的动作摘要，不传按键内容或逐键时间线。远端鱼获提示不改本人模式或个人资产；断线恢复不补播积压动作。

### 5.1 同图成员、位置与收获

用户已定：同房好友在同一地图显示实际角色、各自的钓鱼/摸鱼动作及收获。创建/加入时先自动安排位置，岸边和浅水均可在连续范围内主动选位，不采用每人独立钓台。空间规则统一引用[09 同图多人选位与表现](<09 同图多人选位与表现.md>)。

网络至少承载共享地图实例/版本、成员ID、当前模式、区域及确认落点、位置修订/占用状态、动作摘要与带获得者ID的收获表现。位置坐标属于地图空间，与每台电脑窗口的桌面位置分开。

自动安排和并发选位必须有一致确认机制，所有客户端看到相同落点，不能各自随机放人。加入/重连先恢复当前位置快照；旧地图、旧连接、旧位置消息不覆盖现状，历史动作不集中补播。确认离开后按房间生命周期释放占用；Q19已定确认断线立即移除并释放，重进重新安排；房主断线另触发Q18自动迁移。

单击选位、按住角色/水面拖窗；选位时允许成员尽量靠近，必要空间确实不足则保留原位并反馈。不能自行采用旧提案的最近空位重定向，也不能为避免并发而增加未定的大间隔；并发请求的确认顺序与去重由一致性机制处理。

好友动作必须可见且有归属，降噪只压缩频率/音效，不得把好友变成静止装饰。收获展示锚定获得者，不具备给本人发鱼、发钱或推进计数的权限。

B3已按用户答复定下4人、房主公共切图、自动迁移和0秒保位，房主统一确认位置；个人收益架构按Q16授权开发决定。网页先验证模拟空间/表现/状态，完整真实联机须PC另跑NET验收。

具体联网/资产权威未选前，这些作为接口要求与原型验证目标，不批准某一整套网络实现。

### 6.1 PC窗口尺寸与跨屏恢复（Q6/Q7）

规则来源为用户对Q6的C/B选择、Q7的A选择，以及补答“保留你选择的占屏比例”。本节只约束PC原生窗口；网页版仍为模拟桌面宽高各1/4，随整页等比缩放。

- 玩家可从右下角拖动自由缩放，始终保持16:9；不采用设置三档大小。最小可交互展开窗口为400×225逻辑像素，不是400×225物理像素；系统DPI缩放不改变逻辑下限。收起头像不是展开窗口，不受此展开尺寸约束。
- 未有有效大小偏好时，使用约整屏1/16的初始目标；已有有效PC偏好时保留，不每次重置默认。缩放取消保留操作前尺寸及已保存偏好，成功结束才更新偏好；重算显示大小不等于玩家重新选择偏好。
- 为同时满足任意屏幕比例与16:9，设当前显示器完整屏幕的逻辑宽高为W、H，基准宽度B=min(W,16H/9)，基准高度为9B/16。保存的占屏比例s=玩家选定的窗口逻辑宽度/B，未设置时s=1/4。16:9屏上s就是窗口宽占屏幕宽的比例；不使用物理像素比或只按主屏计算。
- 在当前屏恢复的目标逻辑尺寸为(sB,9sB/16)，再按400×225下限及当前屏可用工作区内能容纳的最大16:9尺寸限制显示。尺寸取整由原生布局处理，允许至多1个物理像素的栅格误差；不能累计偏移宽高比。因下限、工作区或DPI暂时受限时，保留原s，不把被限制后的实际尺寸回写为新的玩家偏好，回到能容纳的屏幕时恢复原比例。
- 跨屏拖动期间保持当前逻辑尺寸，松手后才按目标屏重算；目标屏判定沿用原生窗口的显示器归属，跨屏边界判定、抗抖和坐标换算属于开发实现。分辨率、系统缩放变化或副屏移除后移回主屏时同样重算。重启先选有效显示器（原屏仍在则原屏，否则主屏），再按该屏恢复。
- 保留窗口在所在屏可用工作区中的相对位置；尺寸变化后若会不可达，则平移回可用范围，不自动锁底或移动其他应用。无可移动余量的轴留在可用边界。屏幕工作区本身不足400×225逻辑像素属于低于最小布局的环境：不偷偷降低下限，沿用窗口可找回要求，至少保留恢复/移动入口可达。
- 保存显示器标识、相对位置和s，窗口设置与鱼获/金币/收藏存档分开。不存在或损坏的窗口尺寸设置仅回退到初始尺寸，不清玩法资产。存储格式、平台API、工作区裁剪与命中更新由开发完成，不在策划中指定引擎或配置代码。
- 缩放热区与窗口拖动的输入均隔离于捕鱼；缩放只改变视图尺寸，不能改地图落点、鱼体长或好友位置数据。布局、渲染和命中区域必须按同一DPI转换更新。新增的缩放提示若实际需要，语义与位置见01，逐字文案【交文案策划定】；本次不新增三档名称。

数字例子：两屏均16:9且系统缩放100%，2560×1440屏上把窗口调为800×450，s=800/2560=0.3125；拖到1920×1080屏松手后为600×337.5逻辑像素，再由渲染栅格取整。返回原屏恢复800×450。若在1280×720屏恢复s=1/4，目标320×180受下限限制，显示400×225，但s仍为1/4；回到1920×1080时恢复480×270。

## 7. 联动改动与旧建议替代

整窗穿透不再是唯一交互方案，替换为用户可开关的透明负空间穿透和明确的角色/水面拖动区。半屏/1/4、底部铺满宽度、模式仍待互斥的说明均失效。
