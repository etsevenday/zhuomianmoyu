# 同图多人选位与表现

系统编号：SPACE-001；单案修订：0.1；更新日期：2026-11-16。
规则状态：基础设计；需求及两项交互答复已获用户确认，仅策划修订，尚未程序接入。

## 1. 目标、职责与边界

用户明确补充：好友加入后，必须在同一地图里看到彼此的角色、钓鱼/摸鱼动作和收获。地图应提供一整片可以点击选择位置的区域，不为每位好友单独预制钓台；下水摸鱼同样可以选位置，系统先自动安排。

本系统唯一维护地图活动区域、自动安排、主动选位和多人空间表现。捕获概率与资产结算引用02、04，房间权限及连接生命周期引用05。位置选择不裁定旧概率、存量进度、离线收益、房间人数、引擎或网络权威方案。

## 2. 玩家流程

创建/加入房间 → 获得当前共享地图及成员快照 → 系统根据本人当前模式自动安排合法位置 → 显示本人和同图好友 → 各自执行当前模式动作 → 对应角色附近展示其收获。

玩家无需先选座才能出现在地图。主动换位时，从当前模式对应活动区域选择目标 → 校验可用位置与最新占用 → 确认后同步实际落点 → 所有人看到相同结果。选位只移动自己的角色，不能移动好友。

切换模式时，系统为角色安排新模式适用的区域；岸边钓鱼和下水摸鱼不能只换工具而把角色留在错误地形。此处不决定切换前进度如何处理。

## 3. 对象与主数据

| 对象 | 最少语义字段与约束 |
| --- | --- |
| 地图区域 | 地图ID、区域ID、地图版本、连续可用范围、支持模式、边界与禁入装饰；范围用地图空间定义 |
| 岸边活动区域 | 路亚、手竿角色可落座的连续岸线/岸面及其竿线、水面动作空间 |
| 浅水活动区域 | 下水摸鱼角色可选择的连续浅水范围及探水、扑腾、收获动作空间 |
| 成员位置 | 房间及地图实例、成员稳定ID、区域ID、实际落点、朝向、当前模式、位置状态及修订标识 |
| 占用与请求 | 当前占用快照、成员ID、目标点、请求唯一标识、处理结果；同一请求重试不能重复占位 |

地图位置与桌面窗口位置是两套数据。不同分辨率、DPI或窗口位置不能改变成员的地图落点；坐标编码、采样和动画实现由开发选型，不在本案指定像素坐标。

## 4. 区域、安排与选位规则

### 4.1 连续可用区域

三张地图都需预留连续岸边和连续浅水活动范围。岸边可以是一整片自然岸线、石岸或连贯地面，不能画成“一人一座专用钓台”的固定小岛、隔间或编号座位。浅水同样不是几个孤立的预制站位点。

玩家点击区域内目标位置，系统按§4.3的必要实体空间规则判断落点；动作范围用于构图和归属可辨，不整体变成排他空间。内部可用采样点或导航数据，但不能据此把玩家可选范围限制成少量固定座位。装饰、边界和已有角色可形成局部不可用范围。

每张地图的岸边、浅水区域均须按最终房间人数上限检查满员布局，覆盖所有成员都选择岸边钓鱼、都选择摸鱼以及混合模式。人数上限仍待定，不能从示例两人或旧四人建议推断。上限和角色母版确定前，满员容量验收保持未完成。

### 4.2 系统自动安排

首次进入或没有当前地图有效位置时，系统先在对应区域安排可用位置。安排须保持角色、主要动作和鱼获归属可辨，避免把多人或竿架完全叠在一起；不要求玩家先购买或认领独立钓台。

已确认的位置由房间一致性机制协调，不能让每个客户端各自随机安排同一成员。切换地图后的旧位置不直接当成新地图坐标使用；新地图准备完成后再按其有效区域安排。

位置安排尚未成功时，不把旧位置显示成新位置或宣称已经落座；界面提供正在安排、失败及重试/离开的状态语义。位置请求失败不撤销已经保存的个人鱼获。相关逐字提示【交文案策划定】。

### 4.3 主动选位与争用（用户已定）

单击当前模式可用的岸边/浅水位置，为自己的角色发起一次换位；按住角色/水面拖动整个窗口。按下先由交互处理，释放时确认为非拖动才提交选位；已形成拖动的手势在释放或取消后不再提交选位。手势阈值与抗抖由开发按系统输入习惯实现，不在此新增固定时长或点击收益。

允许玩家尽量靠近，不额外设置社交距离或强行拉开间隔。放置校验只保留角色/装备必要实体空间及可辨要求；竿线、水花等可以交叠的表现不能整体作为排他范围。实际轮廓依据最终母版确定，不用固定钓台或额外空地划分座位。

点击目标能放下则确认该位置；确实放不下时不换位，保留最后一次确认位置并反馈。两人并发选位时根据最新已确认占用作一致处理，不能各端都宣布成功。原问题中的“自动安排到最近合法位置”只是候选建议，用户最终答复为允许靠近、放不下保留原位，本案不默认启用该重定向。系统首次进入/切换对应区域时的自动安排继续按§4.2执行，与主动点位失败不同。

无效区域、边界外、装饰或不支持当前模式的区域不提交有效换位，也不切换地图/模式。处理结果未确认前，保留最后一次已确认位置；取消或失败不产生虚假占位。是否展示落点预览、点击抗抖和移动过渡属于实现表现，不能改变最终位置结果。

## 5. UI、输入与多人可见性

本人和同图好友必须实际出现在场景里，好友列表不能替代角色同屏。路亚呈现拉竿，摸鱼呈现探水动作，手竿呈现对应等待姿态；各自的当前模式独立选择。三模式互斥作用于每位玩家，不表示全房必须采用同一种模式。

普通动作可合并降噪，但不能把好友做成静止装饰。收获表现锚定获得者的地图位置，能区分谁抓到鱼；多人同时收获时分别保留归属，不集中显示成仿佛全是本人所得。提示不得抢工作焦点、自动展开管理面板或给本地资产发奖。具体文字、成员标识和提示措辞均【交文案策划定】。

选位、预览、确认、取消、拖窗和菜单操作均归管理/窗口输入，不推进捕鱼计数；前后台输入通道均须隔离同一操作。角色换位置、窗口拖动、独立捕鱼输入是不同事件。

维持16:9小窗、G风格和自然荷塘配色。布局必须预留多人完整动作、工具与收获提示空间；不能用把所有角色缩到不可辨的方式满足满员。UI面板覆盖场景时不删除成员，关闭后恢复最新状态。

透明穿透开关继续默认开启且可关闭。开关只改变透明留白的指针命中，不改变区域可用性、成员占用或地图位置；不把透明天空和纯装饰补成整窗选位热区。

## 6. 状态、同步与恢复

所有客户端共享当前地图版本、成员身份、模式、区域与确认落点。落点、占用变更须有一致确认结果；网络权威采用房主、服务端或其他方案仍待技术专题选择，本案不因此选定架构。

并发选位必须基于最新占用形成可一致复现的结果，不能两端各自显示抢位成功。重试使用请求唯一标识；迟到的旧地图、旧连接或旧位置修订不能覆盖当前落点。

加入/重连先恢复当前成员及位置快照，再接收新动作；不重播历史拉竿/摸鱼/收获风暴。确认离开后释放其占用，短暂网络抖动与失效成员的判定沿用最终房间生命周期政策，不凭单次丢包任意删人。

每位玩家的鱼获仍按其个人资产接口处理，远端只同步表现；同一鱼获事件重复到达不能重复发奖或无限重复提示。地图位置不从PNG读取，也不把桌面窗口坐标发作成员落点。

当前没有游戏实现或旧档，不新增迁移脚本。断线重连是否保留原位、保留多久及跨会话位置偏好，与最终房间生命周期一起收敛；本次只要求重连后快照一致、无重复占用。
