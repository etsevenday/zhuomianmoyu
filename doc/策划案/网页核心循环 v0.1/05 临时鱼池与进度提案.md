# 临时鱼池与未完成次数的保存

系统编号：WEB-CONTENT-001；修订：0.2；日期：2026-11-17。
规则状态：六鱼表、体长与权重、各地图各玩法分别记住次数均已获用户确认；不是旧12鱼草案转正。

## 1. 用户已定：分别记住次数

- 总累计从新玩法档建立起计，刷新后继续保留；各模式累计也保留。出鱼只清当前模式当前周期，不清历史总数。
- 主动捕获周期按“模式×地图”分别保存。切走冻结，切回继续，不将路亚进度兑换给摸鱼，不把一图的临近保底带到另一图。
- 成功时使用该周期对应的当前地图鱼池；输入、模式/地图切换与节点结算按统一事件序列生效，一次输入只属于一组周期。
- 收起不自动展开；推荐收起后继续接受合格页面工作输入并结算，头像可有克制活跃反馈；恢复后显示当前数据，不回放积压动作。主动关闭游戏小窗或退出网页后停止新增输入，重新打开恢复已保存状态，不补网页外输入。
- 手竿时可统计页面有效输入为总数/该模式统计，并做轻装饰反馈，但不推进路亚/摸鱼周期，也不以按键代替30分钟。
- Q8后续裁定：本轮接通手竿真实计时与出鱼，按§1.1执行；取代此前“本轮不接完整手竿计时”的范围，不把尚未改动的B1占位实现视为已通过。

用户通过400次的例子明确选择分别保留。例：地图一路亚已有400次，切去地图二/摸鱼不会消耗或清掉这400次；返回地图一路亚后再输入100次即可到该组的500次判定。

### 1.1 手竿有效时间与结算（Q8）

- 本轮启用，满1800000毫秒（30分钟）产生1条正常鱼获，多余有效毫秒带入下一轮；使用当前组所属地图的§2鱼池、权重和毫米体长，不新增手竿专属鱼或随机失败。手竿常规出鱼不标成路亚/摸鱼的节点“保底”。
- 每张地图保存自己的手竿有效时长及已完成周期序号，初值0；未满一轮时已保存进度范围为0至1799999毫秒。切地图/切其他玩法先结清旧组已符合条件的时间，再暂停旧组；切回接着计，不清空、不挪给新图。先按旧组结算再切换，不能把临界出鱼交给切换后的地图。
- 游戏网页开着、当前玩法为手竿、游戏小窗未主动关闭、存档已就绪且本页有写权时具备计时资格；切到其他标签页或浏览器最小化不主动暂停。收起为头像继续；点击“×”关闭小窗、退出网页、切走手竿或失去写权则停止新增时间，恢复资格重新建立时间检查锚点。
- 按用户采纳的规则检查真实经过时间：相邻有效检查间隔Δ满足0≤Δ≤300000毫秒时计入；Δ>300000毫秒则整段排除，不按5分钟封顶计入。恰好5分钟仍可计入。负间隔不减进度也不发鱼，重建锚点。检查频率属于开发实现，不用定时器回调次数代替真实有效时间。
- 上述“超过5分钟排除”是本轮明确采用的近似排除政策，不能据此声称可靠检测到原生电脑睡眠；后台长时间未执行检查也会按同一规则排除。状态详情使用TXT-STAT-011/012说明，不把这段补成离线收益。
- 加载/刷新只恢复最后成功保存的时长与周期；以当前恢复时刻重新建锚点，不从上次保存的墙钟时间补算关闭、睡眠或刷新之间的离线时段。没有计时字段的B1旧档为各图补0毫秒，不动原输入进度、鱼获、金币、外观和已有记录。
- 一次出鱼的有效时长扣除/余数、周期序号、稳定捕获事件、鱼个体及记录须同笔保存。失败重试沿用同一结果，不能因刷新/重试多发或重抽；未确认结果不发布成功提示或未读数。只读页不另计时发鱼。
- 手竿时页面有效输入仍仅加总累计/该模式统计与装饰反馈；计时检查和自动出鱼不增加输入次数，键鼠也不能加速手竿30分钟。静音、打开管理面板和更换外观不改变计时资格。

### 1.2 记录页（Q9）

本轮记录页为6种临时鱼列表，顶部显示已发现数量/6。已发现项显示鱼外形、名称、最长体长、累计捕获数及首次捕获时间；新档0/6。未发现项只显示用户指定“？”，不显示真实名称、轮廓或可捕地图，也不在悬停/辅助标签泄露出处。已发现的持久记录不因出售、收藏或取回而删除，不做逐条捕获流水；交易账本仍是另一功能。手竿正常鱼获与主动正常鱼获使用同一记录规则，开发注入继续保留来源标识，普通游玩验收不靠注入完成。

## 3. 内容升级与旧示例

首次真实玩法档建议为空鱼篓、空纪录，初始缸1个、基础外观四类；旧SampleData的两条排版鱼不自动变成可出售资产，也不在每次加载时重发。

本表使用独立内容版本和TMP内部ID。建议后续正式鱼表上线只影响新增捕获，已获得临时鱼保留ID、体长、外形和收藏/出售资格，不静默改种、改尺寸或清空；正式映射需另行批准。

开发注入鱼与正常节点捕获分开来源；普通游玩验收必须从真实页面输入获得本表个体，不能只用开发按钮注入通过验收。源内容及外形缺失时不能生成没有展示资源的收费/可交易幽灵对象。
