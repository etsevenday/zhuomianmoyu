# 动作、计数、金币与可操作界面

系统编号：WEB-UI-001；修订：0.2；日期：2026-11-17。
规则状态：用户要求动作/计数/交易功能已定；本文件为本轮界面适配，经济参数以04获批后的配置为准。

## 1. 常态界面与计数框

计数和金币共用现有不透明底栏的信息区，保持原底栏高度，不向上遮挡连续岸边/浅水，不恢复左上标题、九点柄或整条顶栏底板。右侧四入口可使用紧凑图标，完整功能语义在悬停/主动查看时提供。

```text
         透明留白                         [房间][声音][收起][关闭]
       原有角色、连续岸边/浅水与输入动作区域

┌────────────────────────────────────────────────────────┐
│[模式▼]  [总累计 N          金币余额 B]   [鱼篓][收藏][记录][更多]│
│         [本轮 n/下一节点   输入/保存状态]                     │
└────────────────────────────────────────────────────────┘
```

这是480×270示例的功能线框，不是带白底的新增场景资产。底栏中部两行展示，模式和管理入口保留可用热区。若显示缩写，悬停/详情必须可见完整整数；不得截断数据或把输入数当作金币。

总累计不因出鱼归零，当前周期显示当前模式真实进度。路亚下一节点从500切到1000，摸鱼依次指向下一整200节点并在2000标示保底；不能将每次失败后的下一节点写成额外增加1000/2000。Q8已要求接通手竿计时，进度显示本地图真实已过时间/30:00，状态与剩余时间按05 §1.1及文案定稿表，不再显示“计时未开放”。

输入状态取自网页实际焦点/可见性与输入服务，保存状态取自存档结果；“后台输入”演示开关不能把失焦状态伪装为正在全局记录。普通状态使用安静图标/可查看说明，避免反复弹窗。

## 2. 每次有效输入的动作

| 情况 | 可见反馈 |
| --- | --- |
| 路亚一次有效输入 | 在本人最后确认落点短促提竿，前爪、竿尖及局部水面响应 |
| 摸鱼一次有效输入 | 在本人最后确认浅水落点探水一次，手套/前爪及局部水花响应 |
| 高频输入 | 接受数不丢，短动作重触发/融合，停止后不长时间串行补播 |
| 捕获节点成功 | 保存结果后播放独立成功表现，真实鱼个体进入鱼篓；普通提竿不等同成功 |
| 管理操作 | 正常按钮/选位/拖窗反馈，不触发捕鱼动作或加计数 |
| 好友表现 | 仅驱动对应好友，收获有获得者归属，不推进本人周期或资产 |

动作始终围绕地图落点，不追随工作鼠标改变钓点，也不拖动整个窗口。实际输入统计以事件接受结果为准，不以播放了多少水花来计数。静音只影响声音，不影响动作和统计。

### 2.1 鱼获卡片＋鱼篓新鱼数量（Q10选1＋3）

每个已成功保存的捕获事件同时驱动头顶小卡片和底栏鱼篓新鱼数量，不是二选一，也不能由两个展示各发一条鱼。卡片显示最新一条鱼的样子/体长及其主动节点保底标记，4000毫秒后消失；卡片尚在时又有保存成功的新鱼则合并数量并以最后一批确认时刻重新计4秒。手竿常规出鱼不加主动节点保底标记。卡片不抢焦点、无自动提示音、不遮选位区；收起期间不强行展开，恢复时不补播过期卡片。

单击卡片打开鱼篓并选中卡片中最新的仍在鱼篓个体；该鱼已移出时仅打开鱼篓，不复活/复制个体。查看、消失和关闭卡片均不改捕获资产。

新鱼数量表示已保存且尚未在鱼篓中确认看过的捕获个体数，初值0，非负整数。新鱼在鱼篓未打开时到达则增加；卡片自行消失、收起和换图不清除。打开鱼篓并实际显示当前列表后清除本次已经显示的未读项，不误清显示之后新到的鱼；鱼篓已打开且新鱼已实际显示时可直接视为看过。点击卡片进入鱼篓也执行同一查看规则。鱼不再属于鱼篓时不保留指向空对象的未读项。

保存稳定的个体ID/已读依据，正常刷新不重复加同一鱼，未读状态随档恢复；升级旧B1档不把全部历史鱼一次标新，只从本规则生效后的新捕获开始。数量是提醒，不是鱼篓总条数，不因手动注入作为普通游玩验收。该提醒不新增独立全屏遮罩或顶部栏。

## 3. 卖鱼与收入在哪里看

鱼篓选中个体后显示外观、准确体长、当前位置、出售资格、单价及放入收藏入口。支持主动多选时显示选中数和总价，不自动把新抓到的鱼加入已确认批次。

出售：选择个体 → 查看报价 → 确认数量/收入/售后规则 → 提交并显示处理中 → 保存成功后鱼退出持有、钱包增加 → 金币附近显示短到账反馈，可查看出售回执。

常态底栏始终有真实可用余额；鱼篓与皮肤面板顶部重复展示同一份钱包，并提供账本入口。账本显示交易时间、操作类型、个体/外观引用、金币增减及交易后余额。钱包、回执、动画都读同一已提交结果，不能各算一份。

确认前取消不改资产；提交后关面板不等于撤销，重新打开查询原请求结果。失败保留原鱼与原余额，不播放已到账成功。只从鱼篓出售，收藏鱼先取回；具体售价及售后规则等待04参数包确认。

## 4. 收藏与背景

鱼篓选鱼 → 放入收藏 → 显示唯一初始缸及占用/20 → 提交成功后移动同一个体。满20条时按钮说明原因，鱼留鱼篓；不能先删除来源。

收藏页显示真实缸内个体、相对尺寸及占用；可主动选择鱼取回鱼篓，可设当前缸为观赏背景。取回后背景同步更新。背景保持角色、计数、钱包与管理入口可见，不改变捕鱼地图/鱼池/落点，也不把所有鱼放大成一样大。

Q11采用用户自定义方案：鱼缸位于原有透明画幅内的最底层，钓鱼场景、角色及UI覆盖其上；鱼只在缸内游动，可以沿原边界绘制缸框，不扩大原画幅。不是把观赏鱼叠在当前地图水面上。默认不设背景，玩家主动设置/取消。唯一层级、边界与点击规则见03 §3。

首次空鱼篓、空缸和存储不可用都有明确语义；不能继续塞两条固定示例鱼假装玩家已收藏，也不显示未拥有的第二个缸为已开放。

## 5. 皮肤在哪里抽、怎么装备

沿用现有“更多→皮肤”。皮肤页显示四类浏览页签、内容预览、已拥有/未拥有/当前装备、金币余额、抽取成本、当前池内容和实际概率入口。04建议为统一池，分类仅筛选浏览，不能因切换页签悄悄变成分类抽取。

抽取：核对100币成本/池内容/连续重复状态 → 发起唯一请求 → 同笔保存扣币、重复返20或解锁、连续重复次数 → 展示结果及实际余额 → 玩家选择装备或关闭。结果动画可跳过，不能跳过资产或重抽。普通抽为12款各1/12；连续重复4次后的下一抽只从未拥有款抽取，获得新款后清零。

余额不足表达所缺金额并保留浏览；全拥有后停止抽取；资源或保存未就绪不能收费。未拥有可预览但不能装备，抽到不自动换装，四类装备分别保存，随时可切回默认。

## 6. 文案与计划验收

计数、计时、金币、输入/保存状态、确认回执、名称描述及异常原句按[本轮文案定稿](<../文案交接 v0.1/03 B0-B1界面文案定稿.md>)接入。来源为用户明确授权总控补齐，功能语义不另外随意改写成另一套字符串。

- WU-01：常态能找到总累计、本轮周期和实际金币余额；不打开鱼获提示也能看余额。
- WU-02：正常有效输入时角色有可见短反馈；管理操作不加数，输入停止后不持续补播。
- WU-03：计数/钱包/回执同时出现时，连续岸边/浅水仍可点选，角色与竿尖可辨。
- WU-04：卖鱼前能核对报价，成功后鱼、钱包、回执一致；失败不假成功。
- WU-05：收藏、取回、设背景真正修改并恢复数据，不仅切换预览图。
- WU-06：更多能进入皮肤抽取页，能预览四类内容、看概率、抽取、装备并恢复。
- WU-07：演示后台开关不改变网页输入能力；页面外正常输入不伪造计数。
- WU-08：同一已保存鱼获同时触发4秒卡片和新鱼数量，仅有1个资产；卡片超时不清新鱼数量，打开鱼篓后清已显示的未读项。
- WU-09：连续新鱼合并卡片显示最新鱼与数量、重新计4秒；主动节点保底标记只属于该实际鱼，手竿不冒充保底。
- WU-10：收起/恢复不强行展开或补播过期卡片；保存失败不发已获得卡片/未读数，刷新不重复标同一鱼。
- WU-11：新档未设背景；设置后鱼缸在原画幅最底层、被钓鱼场景覆盖，缸框和鱼不截获点击、不超边界。
