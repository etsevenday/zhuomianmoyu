# 鱼获、收藏与资产存档

系统编号：WEB-ASSET-001；修订：0.2；日期：2026-11-17。
规则状态：20条初始鱼缸与可用收藏需求由用户确认；出售按04委托协调价表，抽取按用户选定的允许重复/返20/四连重复规则执行。

## 1. 个体与初始状态

每条捕获鱼有稳定唯一ID、内容版本、来源类型、鱼种内部ID、体长整数毫米、捕获模式/地图/时间、捕获事件ID及当前唯一位置。正常捕获、开发注入和旧示例来源分开记录，不能将B0每次重建的SampleData当成可反复领取的资产。

本轮收藏初始1个免费鱼缸，容量20条，按个体条数计，不按体长占格。鱼篓本轮无游戏条数上限；这不是浏览器存储无限的承诺，存储失败按§5处理。鱼缸满时鱼留原鱼篓，不能自动出售、丢鱼或先删后补。

更多鱼缸购买价格/解锁仍另定；当前不显示虚假的购买成功。旧图中的第二个鱼缸不代表初始就有两个，未拥有容器只能作为待开放语义或不显示可用状态。

## 2. 收藏的可操作闭环

鱼篓选中本人持有个体 → 选择放入收藏及目标缸 → 校验个体归属、目标存在和余量 → 原子保存新归属 → 鱼篓移除同一个体，鱼缸显示同一个体。

收藏内选择个体可取回鱼篓。初始缸满、并发状态改变、保存失败或重复点击时，保留最后成功确认的归属，不复制或删除。操作状态包括待提交、提交中、成功、失败/可重试，提示语义【交文案策划定】。

收藏显示、鱼篓详情与纪录共用同一体长数据。同镜头统一尺度，大鱼与小鱼按真实相对长度体现；镜头缩放作用于全缸，图鉴缩略图另作排版，不能据此归一每条观赏鱼。

## 3. 设为观赏背景

选中的本人容器可设为当前收藏观赏层，真正显示其持有个体；入缸/取回后背景同步更新，不继续显示已移出或已售鱼。空缸可以作为空观赏容器显示，不伪造鱼获。

观赏层与捕鱼地图、鱼池、角色落点分开保存。换观赏背景不切产出地图，不改变模式/节点/鱼种权重；角色动作、计数、金币和管理入口仍可见。保留透明负空间与既定可选区域，不把整窗变成阻挡桌面的不透明大矩形。观赏鱼不是可再次捕获的对象。

Q11后续裁定取代B1开发记录§2的“鱼游在当前地图水面里、不另画鱼缸”假设，具体如下：

- 缸位于游戏内部的最底层透明背景中，使用原场景内容的画幅边界；当前网页逻辑场景为1600×900，渲染时随原窗口等比缩放，不增大画布、不多开悬浮窗、不越出原像素边界。
- 可沿原边界向内绘制G风格的鱼缸轮廓框架；玻璃/背景留白保持透明，不用不透明大矩形填满桌面。鱼、鱼鳍、水花和游动轨迹均裁切在缸内，不因描边厚度或动画溢出画幅。
- 从底到顶：透明桌面之上为缸框/缸内鱼，之后是钓鱼场景岸边/水面/装饰、玩家角色与工具、鱼获卡片/底栏/按钮/管理面板。实体钓鱼场景正常遮住其后缸景；不能把缸鱼再画到地图水面前方冒充底层。
- 框架、玻璃和缸内观赏鱼均不接指针，不新增可拖动/选位/捕获热区。透明穿透开关及原场景命中不变，岸边/浅水仍可选位；管理鱼只须进入收藏面板。
- 新档默认不设置观赏背景。玩家从收藏主动设置/随时取消；取消隐藏本观赏层，不移走真实鱼。主动选择空缸时可显示空缸框架，但不造鱼。
- 缸内全部鱼仍用同一尺度，允许整体镜头适配当前最长鱼，不能逐条归一；相对体长、个体ID及归属不因层级改变。入缸/取回/出售后的实际归属及时更新背景，不保留幽灵鱼。

## 4. 资产事务合同

| 操作 | 同一次成功提交必须包含 |
| --- | --- |
| 捕获 | 节点结果、鱼个体、当前周期重置/失败状态、去重标识 |
| 收藏/取回 | 归属位置、容器余量、背景引用及档案修订 |
| 出售 | 可售资格、个体出售状态、金币增量、出售回执及操作去重 |
| 抽取 | 可支付余额、扣100、锁定结果、重复返20或新增外观、连续重复次数、抽取回执，全部同笔保存 |
| 装备/设背景 | 所有权校验、当前装备或容器选择 |

同一鱼只在鱼篓、一个容器或已出售状态之一。历史纪录不提供第二次出售资格。远端角色/鱼获展示没有个人资产发奖权限。

## 5. 浏览器本地保存与恢复

资产、计数、周期、金币、外观和回执使用有版本的本地存档；窗口偏好可独立保存。至少维护schema/content/rules版本、档案ID、修订号、事件/操作唯一标识、档案随机上下文、各组周期编号/节点及抽取序号、最后成功提交状态。正常刷新后恢复最后成功提交的完整状态，不能每次载入重发初始鱼、初始缸或金币。

现有PrefsStore及pet.js均静默吞掉读写失败，不能直接复用为资产保存成功的证据。接口必须区分无存档、读失败/损坏、成功载入、保存成功及保存失败。失败不显示假成功，不用空档覆盖读失败的旧档，重试不能重新抽随机结果或重复扣币。

随机结果需可由已保存的档案上下文、规则/内容版本、模式/地图/周期/节点或抽取序号稳定重建。保存失败后即使刷新，重新到同一未完成节点/抽取也不能重新掷一个结果；不能只在内存里临时记住结果。初始化档案上下文应先成功提交，正常捕获/交易才可开始。这用于程序恢复和去重，不宣称可防本地改档。

本地记录受站点来源、浏览器设置、清站点数据和存储额度影响；不是跨浏览器/设备云同步。提供当前保存状态的非打断语义，不把浏览器额度等同于鱼篓游戏容量。[MDN Web Storage](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API/Using_the_Web_Storage_API)

存储命名空间应包含本游戏/仓库标识，避免同一GitHub Pages来源下其他项目覆盖本档；窗口偏好与资产档的键/库名都明确区分。名称是实现细节，不作为玩家可见文字。

多标签页冲突、旧偏好迁移、临时鱼内容保留与计数落盘策略见05，由技术专题给可验证方案。无论选何种存储，资产扣币/加物不能出现半笔完成。

## 6. 计划验收

- WA-01：首次只有1个免费可用缸，容量20条；重新载入不再次发放。
- WA-02：第20条可放入，第21条保留鱼篓；鱼缸满不丢鱼、不自动出售。
- WA-03：入缸/取回前后同一个体ID及体长不变，双方列表无副本。
- WA-04：设为背景后显示真实缸内个体，取回后背景立即更新；捕鱼地图/模式/落点不变。
- WA-05：正常刷新恢复鱼、归属、周期、金币、外观和背景；不重建示例资产。
- WA-06：模拟写入失败/读取失败时不假成功、不覆盖旧档、不复制资产；重试同一操作只完成一次。
- WA-07：收藏和交易的所有管理操作都不推进捕鱼输入。
- WA-08：背景未超过1600×900原逻辑场景边界；框架向内、缸鱼动画被裁切；钓鱼实体遮挡其后的缸景，桌面仍从透明部分可见。
- WA-09：在缸鱼/缸框所在的原透明处点击，开启穿透时命中下层；在原岸/浅水处点击仍按原选位规则，缸不产生新热区。
- WA-10：旧B1已选择的背景保留原容器引用与鱼资产，仅迁移显示层级；新档仍默认不设，取消背景不清鱼。
