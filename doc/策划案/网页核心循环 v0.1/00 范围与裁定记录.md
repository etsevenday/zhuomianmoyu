# 网页核心循环 · 范围与裁定

系统编号：WEB-CORE-001；修订：0.3；日期：2026-11-18。
规则状态：输入、捕获、收藏、次数保存、六种鱼池及重复抽取已获用户确认；售价按用户委托完成三专题协调设定。当前文件不是网页功能已完成的声明。

## 1. 目标与当前差距

用户要求协调各专题，使网页版具备真正可用的收藏、每次输入对应动作、可见输入计数，并追加卖鱼、金币收益显示、皮肤抽取入口及皮肤内容设计。

总循环：页面内有效工作输入 → 当前模式动作与可见计数 → 节点判定 → 鱼个体进入鱼篓 → 出售换金币或收藏观赏 → 金币抽取外观 → 装备外观 → 继续游玩。

核对基线为9d87f17：工作输入还未接入动作/计数，SampleData重建示例鱼篓，收藏/出售/设背景/抽取等按钮禁用，PrefsStore只保存偏好且两层吞存储错误。本轮是从B0展示骨架推进到可用闭环，不是只给禁用按钮换颜色。

2026-11-17后续核对：已拉取B1实现及部署确认346c499。以上9d基线保留为本文件初版背景；当前已部署功能及用户Q答复产生的差异统一见[08 开发差异](<08 B0-B1答复与开发差异.md>)，不能继续把所有核心功能笼统称为未实现，也不能把旧假设验收冒充本次新规则通过。

## 4. 网页输入能力

普通网页接收的是当前页面得到的事件，不能以现有方案捕获用户在其他软件、其他标签页或地址栏里的正常键鼠输入。键盘事件目标是当前处理输入的焦点元素，随后可冒泡到Document/Window。[W3C UI Events](https://www.w3.org/TR/uievents/#events-keyboardevents)、[MDN keydown](https://developer.mozilla.org/en-US/docs/Web/API/Element/keydown_event)

网页内模拟桌面穿透、PWA安装或可点的“后台输入”演示开关，均不能作为已实现全局监听的证据。PC系统输入已由Q23定下默认开、系统级次数统计及自身UI排除，规则见[PC输入正文](<../PC输入 v0.1/01 PC后台输入与开关.md>)，仍待开发实际接入；此前助手桥接评估请求保留，不把评估当作已完成的网页能力。输入范围/失焦状态/演示设置的玩家说明【交文案策划定】。
